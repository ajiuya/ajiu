# Shizuku 工具

Shizuku 让普通应用可以执行系统命令。阿九工作台的 `Shizuku` 工具只使用 **ADB shell（UID 2000）**，可在手机系统上运行 `pm`、`am`、`cmd` 等命令，弥补本地容器（PRoot）拿不到系统权限的短板；不接受 Shizuku 的 root 模式，也不将它作为宿主 Root 的替代入口。

## 前置：安装并启动 Shizuku

1. 从 [Shizuku 官网](https://shizuku.rikka.app/download/) 或应用商店安装 Shizuku。
2. 打开 Shizuku，按应用内指引以无线调试或 ADB 方式启动服务，不选择 root 启动：
   - Android 11 及以上：开启「无线调试」后可直接在手机上启动；
   - Android 10 及以下：需连接电脑用 adb 启动。

## 在阿九工作台中授权

打开「设置 → 软件权限 → Shizuku」，页面显示当前状态：

- **未安装**：点击前往下载安装。
- **服务未运行**：点击打开 Shizuku 并启动服务。
- **未授权**：点击申请授权，Shizuku 弹出授权框，选择「允许」。
- **需要 ADB shell 模式**：服务为 root 模式（UID 0）或无法确认身份。请改用无线调试/ADB 启动；需要宿主 root 时，使用[独立 Root 工具](/guide/permissions#root-工具)。
- **已就绪**：服务已确认以 ADB shell 身份运行且授权完成，AI 即可使用 `Shizuku` 工具。

从 Shizuku 应用返回阿九工作台时，状态会自动刷新。

## 使用与安全

`Shizuku` 直接操作宿主 Android 系统，权限高危，因此在工具授权上按**高危工具**处理：

- **没有本会话授权时需审批**：包括 `ls` 这类只读命令。弹窗提供「拒绝」「仅本次允许」「本会话始终允许」。
- **会话授权按工具记住**：选择「本会话始终允许」后，同一聊天会话后续的 `Shizuku` 调用不再重复请求工具审批，不是只记住这一条命令。授权保存在应用私有存储，重启 App 后回到同一会话仍保留；其他会话与子代理会话不继承。
- **身份与显式提权限制始终生效**：每次执行都必须是 ADB shell（UID 2000）；UID 0 或未知 UID 一律拒绝。涉及 `su`/`sudo` 的宿主操作统一使用 Root 工具；Shizuku 的保守检查也可能拒绝仅在命令文本中引用这些词的情况。已有会话授权不能豁免，不应改写命令绕过；这也不代表能审计任意外部脚本内部行为。
- **禁止与高危保护优先**：项目或全局的 `deny` 命中时仍直接拒绝；灾难性删除或不透明危险命令也不会因记住了 Shizuku 而自动获准，处理方式见 [工具授权](/guide/permissions)。旧项目/全局 `allow` 不能代替本会话审批。

这里的聊天会话授权不能代替 Shizuku 自身的系统授权，也不会扩大 AI 获得的任务范围。宿主 Root 另需默认关闭的本机总开关、已有 root 和系统 su 管理器授权，并且每次单次审批；容器/SSH 中的 `Bash`、`terminal` 使用 `sudo` 不属于宿主 Root，不受 Shizuku UID 限制替代。

## 常见问题

**命令报「Shizuku 未就绪」**

按设置页提示依次确认：已安装 → 服务已启动 → 已授权。设备重启后 Shizuku 服务通常需要重新启动（Android 11+ 可在 Shizuku 内重新开启无线调试启动）。

**已有 Shizuku 会话授权，仍提示需要 ADB shell 或改用 Root**

会话授权只减少正常 Shizuku 工具审批，不会豁免服务身份或显式 `su`/`sudo` 限制。先确认 Shizuku 用无线调试/ADB 启动；真正需要宿主 root 的命令应走 Root 工具及其逐次审批，不要借 Shizuku 绕过。

**`Shizuku` 工具执行失败但没有明显报错**

部分命令需要特定系统权限，`Shizuku` 并不具备所有权限。先查看工具返回的错误和 Shizuku 服务状态；容器内的 `Bash` 与宿主 Android 的执行环境不同，不能靠在容器里运行同一命令来证明宿主权限已就绪。
