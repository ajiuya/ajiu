# Shizuku 工具

Shizuku 让普通应用可以执行系统命令。阿九工作台的 `Shizuku` 工具支持 **ADB shell 与 Root 启动**，可在手机系统上运行 `pm`、`am`、`cmd` 等命令，弥补本地容器（PRoot）拿不到系统权限的短板。实际权限取决于 Shizuku 当前的启动方式，两种身份分别取得聊天会话授权。

## 前置：安装并启动 Shizuku

1. 从 [Shizuku 官网](https://shizuku.rikka.app/download/) 或应用商店安装 Shizuku。
2. 打开 Shizuku，按设备条件选择启动方式：
   - **ADB shell**：Android 11 及以上可开启「无线调试」后在手机上启动；Android 10 及以下需连接电脑用 adb 启动。
   - **Root**：手机必须已有 root，由你在 Shizuku 应用中选择 Root 启动，并在系统 su 管理器中允许 Shizuku。
3. 返回阿九工作台，在「设置 → 软件权限 → Shizuku」申请并允许本 App 使用 Shizuku。

阿九工作台不会替你以 Root 启动外部 Shizuku，也不会为设备取得 root。独立 [Root 工具](/guide/permissions#root-工具)的总开关只控制其自身通道，不代替 Shizuku 的启动和系统授权。

## 在阿九工作台中授权

打开「设置 → 软件权限 → Shizuku」，页面显示当前状态：

- **未安装**：点击前往下载安装。
- **服务未运行**：点击打开 Shizuku 并启动服务。
- **未授权**：点击申请授权，Shizuku 弹出授权框，选择「允许」。
- **身份待确认**：已获授权，但暂时无法读取服务身份。点击重试；若一直不恢复，打开 Shizuku 核对服务是否仍在运行，重新连接后再返回刷新。身份未确认时不会执行命令，不会将它误报成已确认的 root 模式。
- **身份不受支持**：当前服务身份不属于支持的 ADB shell 或 Root。请在 Shizuku 中核对启动方式并重新连接。
- **已就绪**：服务已确认以 ADB shell 身份运行且系统授权完成。
- **Root 已就绪**：服务已确认以 Root 身份运行且系统授权完成，AI 可申请执行 Root 命令。

未授权时先显示「未授权」并提供申请入口，获准后才确认身份；不能读取身份时显示「身份待确认」，不会执行命令或误报为 Root。从 Shizuku 应用返回阿九工作台时，状态会自动刷新。

## 使用与安全

`Shizuku` 直接操作宿主 Android 系统，权限高危，因此在工具授权上按**高危工具**处理：

- **没有有效本会话授权时需审批**：包括 `ls` 这类只读命令。普通调用提供「拒绝」「仅本次允许」「本会话始终允许」，审批时请核对服务身份与完整命令。
- **按当前身份和连接记住工具授权**：选择「本会话始终允许」后，同一聊天会话、同一服务身份和连接下的后续普通调用无需重复弹窗。授权保存在应用私有存储中，但只在身份和连接仍有效时适用；服务重启、断开、切换 ADB shell／Root 或撤销系统授权后，须重新确认。其他会话与子代理会话不继承，ADB shell 授权也不能放行 Root 命令。
- **每条命令单独核验**：执行时仍核对所属会话、完整命令和当前服务身份，并使用仅供本次执行的许可，防止换命令或重复使用。
- **ADB shell 的权限有限**：该身份下显式 `su`/`sudo` 会被拒绝，保守检查也可能拒绝命令文本中对这些词的字面引用。需要宿主 root 时，由你准备 Root 启动的 Shizuku 并单独授权，或使用独立 Root 工具；不应改写命令绕过。
- **禁止与高危保护优先**：项目或全局的 `deny` 命中时直接拒绝。高危命令须带提权参数并由你本人单次确认，只提供「拒绝」「仅本次允许」，已有普通会话授权不能豁免，处理方式见 [工具授权](/guide/permissions)。

命令超时默认 120 秒，上限 1800 秒；高危命令可通过可选的 `elevate` 请求单次确认。这里的会话授权不能代替 Shizuku 自身的系统授权，也不扩大 AI 的任务范围或代替计划审批、插件授权、容器／系统依赖安装确认。独立 Root 工具与 Root 启动的 Shizuku 分别授权；容器/SSH 中 `Bash`、`terminal` 的 `sudo` 仍按各自环境的策略处理。

手机命令输出不会随 SSH 工作区自动存到远端，仍会作为 AI 上下文发送给你已选择的服务商。

插件的 Shizuku 操作仅开放 ADB shell，不继承聊天的会话授权，也不能通过插件工具接口调用独立 Root 或 Shizuku 工具。详见[插件](./plugins.md)。

## 常见问题

**命令报「Shizuku 未就绪」**

按设置页提示依次确认：已安装 → 服务已启动 → 已授权。设备重启后 Shizuku 服务通常需要重新启动（Android 11+ 可在 Shizuku 内重新开启无线调试启动）。

**已选本会话始终允许，又出现审批**

先确认当前聊天会话和 Shizuku 启动方式。服务重启、断开、切换身份或撤销系统授权会使对应授权失效，恢复连接后需按当前身份重新确认；高危命令则始终需要单次确认。独立 Root 授权、ADB shell 授权与 Root 启动的 Shizuku 授权不能相互替代。

**需要 Root，却只显示「已就绪」或提示不能执行 `su`/`sudo`**

当前服务使用 ADB shell。请自行打开 Shizuku，确认手机已有 root，选择 Root 启动并允许阿九工作台使用；返回后应显示「Root 已就绪」，再审阅聊天中的 Root 命令审批。使用插件时仍仅开放 ADB shell，Root 启动不能替插件增加 Root 权限。

**`Shizuku` 工具执行失败但没有明显报错**

部分命令需要特定系统权限，`Shizuku` 并不具备所有权限。先查看工具返回的错误和 Shizuku 服务状态；容器内的 `Bash` 与宿主 Android 的执行环境不同，不能靠在容器里运行同一命令来证明宿主权限已就绪。
