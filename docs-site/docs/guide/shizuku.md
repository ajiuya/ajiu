# Shizuku 工具

Shizuku 让工作台使用系统服务执行 `pm`、`am`、`cmd` 等命令，支持 **ADB shell 与 Root 启动**。实际权限取决于服务的真实身份；能确认宿主系统文件操作只读时默认放行，修改宿主或无法确认是否只读时先审批，可仅本次允许或按同来源及身份授予本聊天会话宽授权。

## 前置：安装并启动 Shizuku

1. 从 [Shizuku 官网](https://shizuku.rikka.app/download/) 或应用商店安装。
2. 打开 Shizuku，按设备条件启动：
   - **ADB shell**：Android 11及以上可使用无线调试；旧系统一般需要电脑 adb。
   - **Root**：设备必须已有 root，由你在 Shizuku 中选择 Root 启动，并在系统 su 管理器中允许。
3. 返回工作台，在「设置 → 软件权限 → Shizuku」允许本 App 使用服务。

工作台不替你启动外部 Shizuku 的 Root 服务，也不为设备取得 root。独立 [Root 工具](/guide/permissions#root-工具)的总开关不替代 Shizuku 系统授权。

## 在阿九工作台中授权

设置页面按真实状态显示：

- **未安装**：前往安装。
- **服务未运行**：打开 Shizuku 并启动。
- **未授权**：申请后在 Shizuku 弹窗中允许。
- **身份待确认**：系统授权已有，但服务身份暂不可读取；核对服务并重连，未确认时不执行。
- **身份不受支持**：服务身份不是支持的 ADB shell 或 Root。
- **已就绪**：实际以 ADB shell 运行。
- **Root 已就绪**：实际以 Root 运行。

从 Shizuku 返回工作台会刷新状态。默认放行不把未知身份或 shell UID2000 报成 Root UID0，也不替代系统真正授予的权限。

## 使用与安全

- **可确认只读默认允许**：读取宿主系统文件不再仅因目标位于系统目录就逐次询问；真实身份、系统权限及禁止规则仍核验。
- **宿主修改或不确定行为先审批**：写入、删除、移动、权限修改，或未知脚本、动态路径、任意程序等无法确认是否只读时，显示完整操作及修改目标或不确定原因。实际只读脚本也可能需要确认，不把未知默认放行。
- **两种允许范围**：「仅本次允许」（`ONCE`）只批当前请求；「本会话始终允许」（`ALWAYS_SESSION`）允许本聊天 session 内 Shizuku 同一 source／identity 的全部后续宿主修改与不确定操作，包含不同命令和目标，不限当前命令。不跨工具、来源、身份或父子／其他会话。
- **宽授权只存内存**：进程重启清除；来源、服务 UID／连接代次、相关 Root 代际、Profile 配置内容或选择、实例改变后需重审。旧版会话记录不转成新的宽授权。
- **每条命令仍有内部执行许可**：绑定完整命令、会话及真实 UID／连接身份，一次消费，不换命令、不重放。有效宽授权可省去重复弹窗，但不是可重复使用的执行票或无限 OS Root 权限。
- **身份变化使旧许可及相关会话授权失效**：服务断开、重启、切换 shell／Root 或系统撤权后，须恢复真实连接再发起新操作，不自动重放旧请求。
- **shell 权限仍有限**：产品不再仅因出现 `su`／`sudo` 字样就拒绝，但命令是否成功仍取决于真实 OS 授权。需要 Root 时应准备 Root 服务或独立 Root 通道，不能把默认放行当作已经取得 Root。
- **明确禁止规则仍优先**：命中项目或全局 deny 时拒绝，不能通过 elevate 或更换写法绕过。

命令默认超时120秒，上限1800秒。`elevate` 仅保留旧版兼容，不是发起审批的前提，也不能覆盖显式 `DENY`、适用的 Root 总开关、真实 OS 授权或宿主修改／不确定操作审批策略。宽授权不扩大 AI 任务范围，不改变当前 CHROOT 来源、实例身份和清理核验及独立创建／停止／移除，也不代替计划、插件信任、依赖准备或未要求的软件安装决定。单条历史任务 UNKNOWN 保留诊断但不单独阻止新任务；异常实例删除在核验通过后无需重启。PRoot／SSH 原有提权和精确完整命令授权规则不变。

::: warning 静态识别不是运行时拦截或隔离
无法确认是否只读时先审批，但判断是有限静态识别，不执行或打开脚本来判定；符号链接、`PATH` 解析和任意程序／子进程的实际副作用不能保证。未知先审批不代表能捕获全部访问，也不是沙箱。不要依赖此检查保护全部手机数据或运行不可信代码。
:::

手机命令输出仍会作为 AI 上下文交给你选择的服务商，不随 SSH 工作区自动归档到远端。

插件的 Shizuku 接口仍限插件桥支持的 ADB shell 能力；内置工具默认放行不会给插件增加 Root，也不能通过插件工具接口调用独立 Root／Shizuku。详见 [插件](./plugins.md)。

## 常见问题

**提示 Shizuku 未就绪**

按设置页面核对已安装、已启动、已系统授权和身份可确认。设备重启后服务通常需重新启动。

**为什么读取系统文件不弹窗，实际只读的脚本却可能要求审批？**

能确认宿主操作只读时默认放行；未知脚本、动态路径或程序内部行为无法确认是否只读时会先询问，识别器不会打开或执行脚本来验证。可仅允许本次，或在本聊天会话中允许 Shizuku 同一来源及身份的全部后续宿主修改与不确定操作，包括不同命令和目标。只打印路径字符串或执行系统基础程序本身不会因该路径就全部弹窗；来源、身份等范围变化仍需重审。

**需要 Root，但只显示已就绪**

当前服务是 ADB shell。自行在 Shizuku 中确认设备具备 Root并选择 Root 启动，允许本 App，返回刷新后应显示 Root 已就绪。工作台不会把 shell 模式自动改报为 Root。

**默认允许仍执行失败**

策略允许只表示当前调用通过工具审批裁决，不保证命令具有所有系统权限或一定成功。查看返回错误、服务状态和实际启动方式；容器中的 Bash 与宿主 Shizuku 是不同环境，不能用一边执行成功证明另一边权限就绪。
