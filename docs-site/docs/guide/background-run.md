# 后台运行

「设置 → 后台运行」集中管理 App 在后台的运行与提醒行为。

## 后台运行保活

开启后通过前台服务和通知降低 App 退到后台后任务被打断的风险，点通知可以回到 App。没有正在执行的任务时仍可保留常驻展示，但**仅为展示通知不会持续占用 CPU 或 Wi-Fi 唤醒锁**。

AI 会话、终端任务、交互终端输入和上下文压缩各自申请并释放所需的保护；一个任务结束不会关闭另一个仍在使用的保护。CPU 与 Wi-Fi 保护由应用集中按实际需要启停，不因多个入口重复持有；手动关闭常驻开关也不等于取消正在运行的任务。

::: tip 长任务与空闲常驻不同
AI 执行或上下文压缩等活动会按需自动申请保护，不要求先打开空闲常驻开关。长时间编译等任务宜使用应用可跟踪的后台终端任务；向已有交互终端输入命令的临时保护最长约 60 分钟，新输入可续期，不代表终端里任意脱离管理的命令都能无限期保活。
:::

### 划掉应用与自动恢复

从系统多任务界面主动划掉应用后，后台保护会暂停，周期保活检查也会取消，不用定时任务对抗你的退出动作。下次主动回到 App 前台时，再按保留的开关与当前活动恢复保护；这不等于自动重跑此前被中断的命令或 AI 请求。

开启常驻时，应用会安排约 15 分钟周期的系统后台检查；系统调度可能延迟，不是每 15 分钟准点唤醒。启动保护失败只做有限次数的退避重试，不会无限重启。通知权限、系统前台服务限制、厂商省电策略、强行停止和进程回收都可能影响实际效果，**保活不能保证永不被杀、永不断网或任务一定执行完**。

### 展示工作与真实任务分开

聊天页不在前台或已经不可见时，可以暂停逐字播放、耗时标签等展示工作，但不会因此暂停模型请求、工具执行、审批等待或完成提醒。回到聊天后显示后台已收到的内容，之后的新内容继续按当前打字速度呈现，不需要从头重播离屏动画。任务的保活与停止仍按上面的规则处理，不以关闭动画代替真正停止任务。

## 屏幕常亮

开启后只要 App 停留在前台，屏幕就不会自动息屏，适合持续观察 AI 任务或终端输出。切到其它 App 或回桌面后自动失效，不影响系统的自动锁屏设置，也不需要额外授权。

长时间开着会多耗电，插着充电器用更合适。

## Agent 完成通知

开启后，当 App 在后台、AI 完成一轮对话时会弹系统完成提醒，点通知回到 App 看结果。通知只是提醒，不会代替你阅读回复或确认操作；完成提醒沿用独立的系统通知入口，锁屏显示受系统通知设置控制，具体结果需回 App 查看。

App 在前台时不弹，避免打扰你正在看的对话。计划被拒绝或没有取得有效批准而结束的轮次，不会作为成功完成发送此通知，也不会借后台完成提醒自动续跑。

## 实时通知

开启后，AI 工作时可显示实时进度通知，用「思考中」「读取文件」「执行命令」「等待审批」等短状态说明当前活动。多个 AI 会话可以汇总展示；同时有终端任务时，还可保留独立的任务列表通知，查看 AI、命令与终端的活动数量，不会因显示 AI 进度而把终端任务隐藏。

- **Android 16 及以上**：系统支持并允许时使用进度样式和短状态，可能被提升到状态栏或厂商的顶部实时区域；是否提升、以什么样式显示由系统与机型决定，不保证一定出现「岛」或固定布局。
- **不支持或无法提升时**：正常降级为可展开的普通文字通知，运行中显示已用时间，不伪造完成百分比。
- **结束与撤销**：本轮结束后通知显示对应的结束状态；完成态最多保留约 5 分钟，回到 App 后提前撤销，不会一直留作运行状态。运行中的实时通知不会仅因回到前台而消失；已结束的提示在回到 App 后撤销。常驻保活或其他仍活跃的任务通知按各自需要保留。

运行期间关闭「实时通知」会隐藏这类进度展示，重新开启后会按当前活动恢复，无需等下一条工具输出。连续输出时，活动变化仍会及时更新；单次普通通知刷新失败不会主动取消已建立的任务保护。通知权限与系统省电限制仍可能影响实际展示和后台运行。

通知只展示简短活动和结果状态，不包含原始命令、执行输出或工具参数；锁屏使用隐藏详情的版本，具体结果与审批仍需回 App 查看。通知的计时用于观察活动，不代替聊天中已保存的[本轮实测耗时](/guide/chat#回复下方的用量与耗时)。

## 授权审批通知

开启后，当 App 在后台、AI 有阻塞等待你处理的确认时会弹系统通知，包括三种情况：请求高危工具授权、向你提问、等待计划审批。多个会话同时等待时合并成一条，逐行列出所属会话与状态（「需要授权」「需要回答」「等待计划审批」）。点通知回到 App 处理，处理完或回到前台后自动收起。

只有**一个待处理项且是高危工具授权**时，通知上会直接带「拒绝」「允许」（只放行本次）按钮，点一下即可完成本次工具审批，不会保存会话授权。需要选择「本会话始终允许」时，点通知回到 App，在工具审批弹窗中选择；弹窗同时提供「拒绝」与「仅本次允许」。若同时有多个待处理项、或待处理的是提问与计划审批，则只显示内容，点通知回到 App 处理。按钮只针对通知所对应的工具审批请求；请求已取消或处理完时，旧按钮不会批准后来的请求。

**计划审批没有通知快捷批准按钮，即使只有一项也一样。** 请回到 App，核对所属会话，点计划摘要卡的「查看计划」阅读完整方案，再选择「批准执行」或填写可选意见后「拒绝并结束」；没有「始终允许」。拒绝或未获有效批准会结束本轮、暂停该会话目标，不会自动重提、补送提醒或用排队消息续跑。待审批计划只在内存中，任务取消时清理，重启 App 后需要让 AI 重新提交，不能用旧通知批准新请求。详见[计划审批](/guide/permissions#计划审批)。

会话授权按发起请求的聊天会话保存，不因从通知进入哪个页面而转给其他会话；子代理也不继承主会话的授权。记住授权后，项目/全局禁止规则和高危保护仍优先，详见 [工具授权](/guide/permissions)。

App 在前台时不弹，避免打扰你正在看的对话。

::: tip Android 13 及以上
首次开启需要通知权限的开关（后台运行保活、Agent 完成通知、实时通知、授权审批通知）时会先申请「通知」权限。如果系统弹不出授权框（权限之前被关过或拒绝过），会有弹窗提示，点「去设置」跳到系统设置页手动开启。权限授予前开关不生效。
:::

系统权限（安装未知应用、存储、电池优化、自启动、Shizuku）见[软件权限](/guide/app-permissions)。

## 切到后台后断网怎么办

把 App 切到后台一段时间后，AI 对话可能中断并提示「网络连接断开」。可能原因包括后台联网限制、进程冻结或回收、网络切换，以及服务商或中间网关超时，不能仅凭这条提示确定是哪一种。熄屏与切后台都可能影响设备的省电策略，前台服务和唤醒保护也不能绕过所有系统限制。

把省电策略改成「无限制 / 不优化」可能有帮助，但不保证能解除厂商的全部后台限制。先检查通知权限与网络，再按下面的设置逐项排查。

按下面的顺序设置，多数情况都能明显改善：

1. **打开上面的「后台运行保活」**，并保留通知栏的常驻通知（不要关掉它）。
2. **在多任务界面给本应用加锁**（各机型操作见下），任务期间不要直接划掉；划掉会暂停本应用的后台保护，需下次回到前台才恢复。
3. **在系统设置里把本应用设为「无限制 / 不优化」，并允许自启动**。

### 常见品牌设置路径

不同品牌的后台与省电入口位置不同，找不到时可在系统设置顶部搜索「自启动」「后台」「省电」等关键词。

| 品牌 | 关键路径 |
| --- | --- |
| 华为 / 荣耀 | 应用启动管理 → 关闭自动管理 → 在「手动管理」里打开「允许自启动」「允许关联启动」「允许后台活动」；多任务卡片下拉加锁 |
| 小米 / Redmi | 省电与电池 → 右上角设置 → 应用智能省电 → 选本应用 → 无限制；应用设置 → 授权管理 → 自启动管理；多任务长按卡片加锁 |
| OPPO / 一加 / realme | 应用 → 应用管理 → 本应用 → 电池使用情况 → 允许后台活动；应用 → 自启动；电池 → 更多设置 → 优化电池使用 → 不优化；多任务卡片加锁 |
| vivo / iQOO | 应用与权限 → 权限管理 → 所有权限 → 自启动；电池 → 后台耗电管理 → 允许后台高耗电；多任务卡片加锁 |
| 三星 | 电池和设备维护 → 电池 → 后台使用限制 → 把本应用加入「从不休眠」；应用程序 → 本应用 → 电池 → 不受限制 |
| 原生 Android 等 | 电池 → 电池优化 → 本应用 → 不优化；若熄屏也断，WLAN → 高级 → 休眠状态保持 WLAN 连接 → 始终 |

各品牌路径会随系统版本变化，以手机实际界面为准。

### 还有几个可能原因

- 有的系统会在省电策略之外，**单独限制后台应用的联网**，请确认本应用未被禁止后台联网。
- 手机开机两三天后后台管理会变严，此时重启一次手机往往能明显改善。
- **AI 长回答在后台中断属于可能情况**：模型长时间没有输出时，网络中间的网关可能断开连接，App 无法完全避免。回到前台先查看会话错误与工具实际结果；网络重试受[偏好设置](/guide/general#网络)限制，不要据通知消失就判断任务成功，也不要未核对结果便重跑有副作用的命令。
