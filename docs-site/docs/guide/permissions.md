# 工具授权

普通工具调用默认自动放行；复杂或高风险任务，以及你明确要求先规划的任务，会先提交计划等待你审阅。计划审批与高危工具授权是两件事，本页分别说明。项目与全局的明确禁止规则在「设置 → 工具授权」中查看和清理；独立的宿主 Root 工具另有默认关闭的本机总开关，并且每次都需单次审批。

禁止规则优先于自动放行；难以撤销、影响共享状态或超出当前任务范围的操作（如强推、修改远端、发消息、提/合 PR）仍需取得你针对该操作的明确确认。AI 生成的命令与内容也应按平台权限、安全边界和项目规则处理。

## 计划审批

想先看方案再动手，可以直接告诉 AI：「先只读检查，提交完整计划，等我批准后再改。」复杂、影响面不明或高风险的任务也应先走这一步；普通小改不强制审批，已明确批准且范围未变的方案不必重复提交。

1. **先只读检查**：AI 了解现状，整理目标、改动范围、实施步骤、风险与验证方式，不先修改文件或执行有副作用的操作。
2. **查看完整计划**：聊天输入区上方出现计划摘要卡，标明标题、所属会话和「等待计划审批」。点「查看计划」，在适配手机与平板的底部审阅面板中滚动阅读完整方案。
3. **批准执行**：确认方案后点「批准执行」，AI 才能继续按已批方案发起操作。批准仅针对当前计划，没有「始终允许」。
4. **拒绝并结束**：不接受时可先填写可选的「拒绝意见」，再点「拒绝并结束」。这会结束本轮并暂停该会话的持续目标；AI 不会自动修改后重提，也不会由排队消息或后台完成提醒自动续跑。需要调整时，在下一条消息中要求修改计划后重新提交。

为避免「先做了再等批准」，与计划提交混在**同一批**的其他工具调用都会标记为未执行，无论它们排在计划之前还是之后。即使批准，也不会补跑这些旧调用，AI 必须获批后重新发起。没有取得有效批准时，本轮同样结束，不会自动再答一轮。

审阅面板会显示发起请求的会话标题，多会话和每个子会话各自提交、各自审批，不会把对一个会话的批准用到另一个会话。收起审阅面板只是暂时关闭详情，可从摘要卡重新打开；停止或取消等待中的任务则会清理对应请求。

**待审批计划只在本次 App 运行期间保留**。重启后需要让 AI 重新提交，不能从历史卡片直接批准旧请求。这与下文重启后仍保留的高危工具会话授权不同。

::: warning 批准计划不等于放开权限
计划批准不扩大你交给 AI 的任务范围，不覆盖项目或全局禁止规则，也不替代 Shizuku 系统授权、Shizuku 工具审批、root 命令或高危操作提权审批。它不是 Agent 工作模式切换。
:::

## 规则的来源

项目或全局的 `deny` 规则会拒绝匹配的整个工具或命令段，优先于自动放行、会话授权和高危命令提权。例如禁止整个 `Bash` 工具后，不能靠命令写法或已保存的会话授权放行它。旧配置中的 `allow` 项可保留或在页面中清理，但不再参与裁决，也不能免除高危审批。

被权限规则拒绝时，AI 会收到拒绝原因；命令段命中时还会显示**命中的规则**与被拦下的**具体片段**（例如「命中规则：Bash(git push)；触发片段：git push origin main」）。应据此核对任务与规则，不应改写命令或更换工具绕过禁止。

普通工具被安全检查或禁止规则拦下时，该调用不会执行；拒绝结果保存后，AI 可以说明原因或在已有授权范围内继续处理任务。单次安全拦截本身不会要求你恢复会话。你在工具审批中主动点「拒绝」仍会结束本轮、取消同批尚未执行的调用；计划未获批准时也仍按上文结束本轮。

## 高危工具审批与会话授权

`Shizuku`、容器/SSH 中显式使用 `sudo`/`su` 的命令，以及适用的高危命令提权，在没有会话授权时会请求审批。以下三个选择**不适用于独立的宿主 Root 工具**，Root 的逐次审批见[下节](#root-工具)：

- **拒绝**：不执行本次调用，不新增长期禁止规则。
- **仅本次允许**：只放行这次调用，下次仍按规则判断。
- **本会话始终允许**：在当前聊天会话中记住授权，匹配范围如下。

| 审批类别 | 本会话记住的范围 |
| --- | --- |
| Shizuku | 按整个 `Shizuku` 工具记住；同一会话后续调用不再重复请求工具审批，但 UID、显式提权限制、禁止规则与高危保护仍有效 |
| 容器/SSH 的 `sudo` / `su` | 按**完整命令精确匹配**，不按命令前缀、程序名或目录扩大授权 |
| 适用的高危命令提权 | 按**完整命令精确匹配**，后续调用仍必须携带提权参数；不代替 Root 逐次审批 |

会话授权保存在本机应用私有存储中，回到**同一个聊天会话**或重启 App 后仍保留；「本会话」并不是指本次 App 运行。新会话、其他会话及每个子代理会话均独立，不继承父会话或兄弟会话的授权。它不会写入项目或全局 `allow` 规则。

Shizuku 的系统授权与聊天中的工具审批是两件事。工具仅允许 ADB shell（UID 2000），root 模式（UID 0）或未知 UID 拒绝；显式 `su`/`sudo` 也拒绝并引导使用 Root。旧 Shizuku 会话授权不能豁免这些限制，详见 [Shizuku 工具](/guide/shizuku)。

## Root 工具

`Root` 在**真实宿主 Android** 上执行命令，不是本地容器中的 root，也不是 SSH 服务器上的 `sudo`。前提是手机已经取得 root、系统 su 管理器允许本应用执行，并在「设置 → 软件权限」开启默认关闭的[Root 总开关](/guide/app-permissions#root-总开关)。App 不为未 root 设备取得 root，也不提供 root 安装或漏洞利用。

- AI 提交完整命令后，每次都必须审批，只有「拒绝」「仅本次允许」，**没有「始终允许」**。已有计划批准、Shizuku 授权或容器/SSH 的会话授权不能替代它。
- 许可只绑定发起的聊天会话、完整命令和本次开关启用周期，使用一次就失效；其他会话或子代理不能借用，改命令也不能沿用。
- 关闭总开关会撤销待审批请求和旧许可，并终止本应用管理中的 Root 进程。关闭后重新开启仍需重新审批，旧请求与旧许可不会复活。
- 终止进程不能撤销已经完成的修改，也不保证终止任意脱离本应用管理的后台进程。请在批准前确认命令目标和后果。
- Root 总开关只保存在本机，不随 App 备份导出或在还原时重新开启；单次许可不作为长期授权备份。

工具接受必填的完整命令 `command`，可选超时 `timeout` 以秒计，默认 120、上限 1800；可选的 `elevate` 只用于必要的高危审批流程，不能绕过总开关、逐次审批或项目/全局禁止规则。未带 `elevate: true` 的高危命令仍会被安全拒绝，携带后也不会变成长期允许。

::: warning Root 输出仍会进入 AI 任务
输出有长度上限，不会自动沿当前 SSH 环境归档到远端；但工具结果仍会交给你已选的 AI 服务商处理。需要读取敏感数据时请谨慎，不要把「在手机执行」理解为「输出只留在手机」。
:::

容器/SSH 的 `Bash` 与 `terminal` 中使用 `sudo`/`su`，仍按原环境的禁止和高危审批策略处理，不会因宿主 Root 总开关关闭而一概禁止；这也不赋予它们宿主 root 权限。

## 多会话并行时的授权

多个会话（含子代理）同时工作时，每个会话可以各自挂起一个授权请求，互不阻塞：

- 授权弹窗顶部会标注**发起该请求的会话标题**（如「会话「重构登录模块」」），可明确区分弹窗属于哪个会话。
- 弹窗在任意会话界面都会展示，处理完自动切到下一个待授权请求。
- 侧边栏会话列表里，**正在等待授权**的会话行左侧指示灯是**橙色常亮**（执行中是绿色脉冲）。据此可以发现被挂起等待授权的后台会话，点进去处理。

计划审批也会标出所属会话，并在侧边栏显示等待审批状态。后台开启「授权审批通知」后会提示「等待计划审批」，但**通知没有直接批准计划的按钮**，需回到 App 阅读完整方案后决定，详见 [后台运行](/guide/background-run#授权审批通知)。

## 页面结构

规则分「当前项目」和「全局」两组，点标题可折叠。

每条规则显示判定图标、工具名、匹配范围与判定。旧配置中的允许项仅供查看与清理，不再改变工具调用行为。

- 项目规则右侧有个加号图标，可以把这条规则**提升为全局**，对所有项目生效；提升后它从本项目列表消失。
- 规则行左滑露出红色删除按钮。

## 高危命令保护

未携带提权参数时，删除根目录、系统关键目录（如 `/etc`、`/usr`）、工作区根目录或用户主目录等灾难性操作会被直接拒绝。含命令替换、子 shell、绝对路径重定向等无法静态判定结构、且疑似破坏性的命令也会被拦截，避免在无法确认目标时自动执行。

仅把输出丢弃到 `/dev/null`（例如 `2>/dev/null`）不会单独触发高危写入保护，普通检查命令无需为此先失败再重试。命令中若还包含危险操作、其他受保护目标或命中禁止规则，仍按相应规则处理；不要通过改写命令规避禁止。

显式提权检查覆盖直接调用 `sudo`/`su`、常见的 `env`、`command`、`exec` 和 shell `-c` 包装，以及命令替换、反引号和分组中的内联命令。禁止规则与高危删除检查也会检查这些可展开的命令。检查依据提交的命令文本，**不能保证识别任意外部脚本内部的行为**；运行不熟悉的脚本前仍应审阅内容。

## 高危命令提权

若被安全防护拦截的操作确有必要，且已取得你对该操作的明确确认，AI 可在支持此参数的工具调用中带上 `elevate: true` 请求审批。容器/SSH 的 `Bash` 与 `terminal` 可拒绝、仅本次允许，或选择本会话始终允许此完整命令；独立宿主 `Root` 仍只允许逐次审批，不提供会话记忆。

即使已保存会话授权，未带 `elevate: true` 的高危调用仍会被安全拒绝；只有携带该参数时才会匹配会话授权或进入审批。禁止规则始终优先，高危保护不提供关闭开关。

## 关于「禁止」规则

对话中的单次拒绝不会产生长期规则。项目与全局禁止规则目前需手动编辑配置文件：项目规则写在 `<项目根>/.aicode/permissions.json`，全局规则写在 `~/.aicode/permissions.json`。手工编辑保存后 App 会在几秒内自动检测并刷新页面，规则立即生效。

配置文件格式：

```json
{
  "permissions": {
    "deny": ["Bash(git push)", "terminal(git push)", "Shizuku"]
  }
}
```

不带括号的工具名（如 `Root`、`Shizuku`、`Bash`、`terminal`）表示禁止整个工具；`Bash(git push)` 表示禁止该工具中以 `git push` 开头的命令段，`Root(命令前缀)` 同样约束宿主 Root 命令段，组合命令里命中任一段也会被拒绝。同一操作若可由不同工具执行，需分别配置相应工具的禁止规则。

::: tip 禁止规则优先
项目或全局任一 `deny` 规则命中时，工具调用都会被拒绝，会话授权和 `elevate: true` 不能覆盖它。如需额外的安全兜底，可在全局 `deny` 里添加规则。
:::
