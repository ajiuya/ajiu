# 自定义提示词

阿九工作台的系统提示词可以自行修改。默认提示词随 App 内置、升级时自动更新；只需将需要修改或新增的片段放入自定义目录即可覆盖或扩展，无需修改 App 本体。

::: tip v1.12.0 起
本文的片段命名规则（`<两位数字>-<名称>.md`）、按数字新增片段、`.no-builtin` 完全禁用开关与 <span v-pre>`{{AICODE_*}}`</span> 变量自 **v1.12.0** 起支持。更早的版本只能放与默认片段**完全同名**的文件来覆盖，不支持按数字新增、`.no-builtin` 与变量。
:::

## 在 App 里管理

也可以不碰文件系统，直接在 **设置 → 提示词** 里管理：

- 页面按编号列出当前选中的片段，**停用的片段也保留在列表中**，右侧徽章标明内容来自哪一层：
  - **项目**：本地工作区的 `.aicode/prompts.custom/`；远程工作区对应 App 私有项目配置目录，不直接写服务器。
  - **全局**：App 私有 `aicode/prompts.custom/`，本地容器中映射为 `~/.aicode/prompts.custom/`。
  - **本地**：App 私有 `aicode/prompts/`（启动时从内置释放的副本）。
  - **内置**：App 自带的 `assets/prompts/`。
- 同一编号先选优先级最高的一份内容，优先级 **项目 > 全局 > 本地 > 内置**，其余被遮挡；只有开关开启时才注入，停用不会退回较低层的同号片段。
- 每个数字片段都有独立开关。**停用不删除或清空正文**，以后可原样重新启用；有工作区时开关写当前项目作用域，无工作区时写全局。项目显式状态优先于全局，包括项目开启可以覆盖全局关闭。未配置时默认开启。
- 按拖拽手柄重排或在编辑页改编号时，启停状态跟随内容移动，不会把被停用的内容意外启用。
- 点一行编辑它的内容。保存默认写到该编号当前生效的层；「本地/内置」不可写，编辑后默认落到全局层，可在编辑页把作用域切到项目层（有工作区时）。
- 所有片段都可左滑；项目/全局片段可删除当前覆盖，并清理被删除作用域中该编号的启停状态，之后按剩余内容和状态重新选择；本地/内置片段的删除按钮为灰色，不可删除。删除与停用不同，停用不会回退来源。
- 右上角「+」可用未占用的编号新增片段。编辑时摘要与正文分开填写；摘要显示在列表和预览页，不会注入 AI。手工编写文件时，开头的 `<!-- 摘要 -->` 同样会被识别为摘要，正文预览会隐藏这段注释。
- 首次进入会自动弹出使用说明公告，右上角 Info 可随时重看。

### 批量删除

列表右上角的「多选」按钮（方框带勾的图标）可以一次删掉多条自定义片段：

1. 点「多选」进入多选模式，每行左侧出现勾选框，整行点击即勾选。只有**项目 / 全局**来源的片段可以勾选，本地与内置来源的勾选框是灰的。
2. 顶部操作条提供「全选 / 取消全选」与删除按钮，最右「×」或系统返回键退出多选。
3. 删除会弹确认框；确认后这些编号当前可写来源的自定义覆盖及相应作用域状态一并移除，各编号按剩余来源与启停状态重新解析，列表随即刷新。

编辑页会避让软键盘；摘要或正文较长时可以上下滚动，继续编辑末尾内容。

App 里的改动与手工放文件完全等价，两种方式可以混用。

## 目录结构

全局提示词与默认副本实际放在 **App 私有的 `aicode` 目录**，与当前选择本地还是 SSH 执行环境无关。本地容器把它映射为 `/root/.aicode/`（即 `~/.aicode/`）；远程服务器用户 home 下的同名目录**不等于 App 的全局提示词目录**，不能假定在服务器编辑它就会改变本页内容。

本地项目提示词放在工作区 `.aicode/` 下；远程项目提示词及开关保存在 App 私有 `aicode/projects/<项目标识>/` 下，按服务器与远程路径区分。远程使用时优先在 App 的提示词页管理。

以下为全局目录在本地容器中的映射：

```
~/.aicode/
├── prompts/          默认提示词（App 启动时全量释放，升级自动覆盖）
│   ├── 00-identity.md
│   ├── 10-communication.md
│   ├── ...           顶层是「静态基线」片段，按两位数字前缀排序（内置最后一个为 99-runtime-context.md）
│   └── agent/        按需注入的片段（不进静态基线，用到时才读取）
│       ├── subagent-base.md       子代理基础运行规范
│       ├── subagent-context.md    子代理运行期上下文（身份/工作区/时间）
│       ├── compact-summary.md     顺序合并历史与已有接手摘要
│       ├── compact-leaf.md        长历史的独立分块摘要
│       ├── compact-merge.md       有序归并各块摘要
│       ├── title-generator.md     会话标题生成
│       └── init.md                /init 命令的指令正文
├── prompts.custom/   你的自定义片段（覆盖或新增，升级不动这里）
│   ├── 50-我的安全规则.md
│   ├── 25-额外要求.md
│   ├── prompts.json   数字片段开关状态（enabled 映射，不是提示词正文）
│   └── agent/
├── skills/
└── docs/
```

片段分两类，命名规则不同：

- **静态基线**（`prompts/` 顶层）：`<两位数字>-<名称>.md`，数字是它的身份，决定在系统提示词里的位置。
- **按需片段**（`prompts/agent/`）：没有数字，用到时才读取（如压缩上下文、派发子代理、生成标题），不新增逐片段开关。

## 命名规则

自定义片段放在 `prompts.custom/`：

- **顶层文件**必须是 `<两位数字>-<名称>.md`（如 `05-开头.md`、`50-我的安全规则.md`）。数字即身份：
  - 数字与某个内置静态基线片段相同（内置数字为 `00`、`10`、`15`、`20`、`30`、`40`、`50`、`60`、`70`、`99`）→ **覆盖**该片段，尾部名称可任意取；
  - 数字不在上述集合里 → 作为**新增片段**，按数字大小插入基线的对应位置（如 `05-开头.md` 排在 `00` 与 `10` 之间）。
- 不符合该格式的文件（如 `notes.md`、`2024-备忘.md`）会被忽略。
- 同一数字有多个文件时只取文件名排最前的那个，其余忽略——请保持数字唯一。
- **`agent/` 子目录**里的片段没有数字身份，按**精确同名**覆盖。

## 加载优先级

顶层数字片段（`<两位数字>-<名称>.md`）按四级来源查找，同一编号只生效优先级最高的一份，找到即止：

1. **项目**：`<工作区>/.aicode/prompts.custom/`（远程模式下是 App 私有目录里对应的项目目录）
2. **全局**：App 私有 `aicode/prompts.custom/`（本地容器映射为 `~/.aicode/prompts.custom/`）
3. **本地**：App 私有 `aicode/prompts/<同名文件>` — 启动时释放的副本
4. **内置**：App 自带的 `assets/prompts/`

`agent/` 下的按需片段（无编号）没有项目层，按「全局自定义（`prompts.custom/agent/xxx.md`）→ 本地 → 内置」三级查找。

所以你只需要放想修改或想新增的那几个片段，其余在未停用时会使用默认版本。开关状态与内容来源分开解析：先确定内容，再按「项目状态 > 全局状态 > 默认开启」决定是否注入。

### 开关配置

App 将数字片段的开关持久化在对应作用域的 `prompts.custom/prompts.json` 中，使用 `enabled` 映射，例如：

```json
{
  "enabled": {
    "40": false,
    "60": true
  }
}
```

这表示在该作用域停用 40、启用 60，不会修改 Markdown 正文。项目文件中的显式值覆盖全局同号值；没有项目值才继承全局，没有任何值则默认开启。不要通过删除正文模拟关闭，也不要以为关闭项目片段后会重新注入全局同号内容。

## 修改方式

1. 在 App 页面选择片段，或在上述实际作用域目录放入文件：覆盖内置片段用相同数字命名，新增片段用尚未占用的数字命名，按需片段放到全局 `prompts.custom/agent/` 下。
2. 编辑内容或调整数字片段开关。
3. **从下一次模型请求生效**，无需重启 App；已经发出的请求不会被改写。

::: tip 下一次请求读取新基线
每次模型请求会重新构建提示词，内容或开关变化也会重新建立上下文估算基线，不继续套用变化前的用量锚点。注意：技能清单、记忆、子代理清单仍是**新开会话**才刷新。子代理若选择注入「主规则（MAIN_RULES）」，同样使用这套启用后的静态基线；其余片段仍按子代理定义注入。
:::

在本地映射目录可通过终端或 AI 文件工具编辑，也可[用文件管理器访问 App 私有目录](/guide/files#工作区文件在手机上的位置)。远程 SSH 服务器的 `~/.aicode` 不是上述 App 私有全局目录，远程模式下请优先使用 App 页面。

## 完全禁用内置提示词

原有「完全禁用内置提示词」总开关继续保留，与逐片段开关独立。在**全局** `prompts.custom/` 下放置 `.no-builtin`（内容随意，存在即生效），或在 App 页面开启总开关后，主代理的系统提示词只由项目/全局自定义目录中已启用的顶层数字片段组成：

- 不再注入任何内置片段，也不再自动附加技能清单、子代理清单、记忆、项目规则、工作区与当前时间；
- 需要哪些动态内容，就在你自己的片段里用下面的变量按需取回；
- 子代理的其他按需注入仍由各自定义决定；选择注入「主规则（MAIN_RULES）」时，数字静态基线遵循同一套来源与启停规则；
- 项目/全局自定义目录中没有可识别且已启用的数字片段时，主代理系统提示词会为空，请确保保留需要的 `NN-xxx.md`。

::: danger 这是"完全接管"
启用后 AI 读到的提示词由你写的片段决定，务必自备身份、工具说明与安全边界等内容，否则 AI 会缺少必要上下文。总开关与逐片段停用都**不会关闭平台或工具硬权限**：项目/全局禁止、Root 总开关、Shizuku 身份校验、会话授权范围与高危命令单次确认仍照常生效；独立计划、插件授权和容器／系统依赖安装确认也需按各自规则处理。
:::

## 可用变量

在片段正文里写这些占位符，运行时会替换成真实内容；清单为空时替换为空字符串：

::: v-pre
| 变量 | 替换为 |
| --- | --- |
| `{{AICODE_SKILLS}}` | 可用技能列表（每行一项） |
| `{{AICODE_SUBAGENTS}}` | 可用子代理列表（每行一项） |
| `{{AICODE_MEMORY_GLOBAL}}` | 全局记忆列表（每行一项） |
| `{{AICODE_MEMORY_PROJECT}}` | 项目记忆列表（每行一项） |
| `{{AICODE_PROJECT_RULES_GLOBAL}}` | 全局项目规则正文（`~/.aicode` 下的 `AGENTS.md` / `CLAUDE.md`） |
| `{{AICODE_PROJECT_RULES_PROJECT}}` | 工作区项目规则正文（项目根目录下的 `AGENTS.md` / `CLAUDE.md`） |
| `{{AICODE_PROJECT_RULES}}` | 等价于 `{{AICODE_PROJECT_RULES_PROJECT}}`，为兼容旧片段保留 |
| `{{AICODE_WORKSPACE}}` | 项目根目录（`~/workspace`，未选工作区时为提示文本） |
| `{{AICODE_ENVIRONMENT}}` | 当前运行环境（本地容器（PRoot） / 远程 SSH 服务器） |
| `{{AICODE_DATE}}` | 当前日期（`yyyy-MM-dd`） |
| `{{AICODE_SUBAGENT_NAME}}` | 当前子代理名称（仅子代理提示词渲染时有值） |
:::

::: tip 变量在任意片段处就地展开
系统提示词里的技能、子代理、记忆、项目规则、工作区与当前时间，默认由内置片段 `99-runtime-context.md` 用这些变量承载；你也可以在自己的片段里写变量，同样会在该处替换成真实内容。想改变这些内容的位置或顺序，编辑或覆盖 `99-runtime-context.md` 即可。
变量只替换为**纯数据**（列表行、文件正文、路径、日期），像「可用技能：」这样的标题与引导语都写在片段文件里，随片段一起编辑。
:::

`prompts.custom/` 里没有 `99-runtime-context.md` 的覆盖时，运行期上下文照常由内置版本注入；若你覆盖了它却没写变量，对应内容就不会出现。

其它占位符（如压缩提示词用的 <span v-pre>`{{INSTRUCTION}}`</span>）不受影响。

## 升级时的行为

- `prompts/` 目录每次启动都会被内置版本全量覆盖，所以默认提示词会随 App 升级自动更新。
- 升级不覆盖 `prompts.custom/` 中的自定义内容与开关状态；在 App 中编辑、启停、删除或重置时，则会按操作更新该目录。

::: danger 请勿直接修改 prompts/ 目录
`prompts/` 目录中的内容在每次启动时都会被全量重置，手动修改的内容在 App 升级或重启后会被覆盖。如需持久自定义，请务必保存在 `prompts.custom/` 目录中。
:::

## 恢复默认

在 App 中删除某个自定义覆盖，会一并清理该作用域中对应编号的开关状态，再按剩余来源和状态解析；仅手动删除 Markdown 文件不会替你清理 `prompts.json` 中的停用记录。要重新启用，使用片段开关或同步清理相应作用域状态。

App 的重置会清理当前项目与全局的数字自定义片段及对应启停状态，但保留 `.no-builtin` 总开关和无编号按需片段。若要重新使用内置提示词，还需关闭总开关；不要把「重置片段」等同于自动关闭 `.no-builtin`。

## 备份与迁移

在「设置 → 备份与还原」单独勾选**提示词**，可保存手机侧全局、已登记本地项目与手机保存的远程项目各层 `prompts.custom/` 内容，包括顶层片段、`agent/` 覆盖、`.no-builtin` 总开关及 `prompts.json` 启停配置；不打包可由 App 重建的内置提示词及默认副本。首次默认关闭，之后沿用勾选状态，与记忆、技能和插件独立选择。

还原预览按来源与项目选择，默认不选且保留同名文件；需要覆盖时先备份当前自定义内容。手机保存的远程项目配置仍按原来源隔离，新设备可新建对应目录，不会套给另一台服务器。还原只是写回自定义内容与状态，不会立即执行其中的任务，也不能授予 Root、插件或其他工具权限；之后的请求按本页加载规则生效，`.no-builtin` 也仍不改变平台权限。具体流程与结果核对见[备份与还原](./backup.md)。

## 注意

- `60-tools-and-paths.md` 这类片段会随工具变更而更新。如果你覆盖了它，App 升级后不会自动获得新版工具说明，AI 看到的工具定义可能和实际不一致。需要更新时手动同步，或删掉你的自定义版本让默认版本重新生效。
- 自定义工具说明应区分宿主 Root、Root 启动的 Shizuku 与容器/SSH 的 `sudo`。普通工具自动放行、禁止规则优先；Root／Shizuku 普通调用可本会话始终允许，两通道与 ADB shell 身份分别授权，关闭独立 Root 再开启或 Shizuku 连接／身份变化后须重新确认。Root／Shizuku 高危命令仍须本人单次确认，容器/SSH 的 `sudo` 与高危提权则按完整命令匹配会话授权。独立计划、插件原生授权、容器／系统依赖安装确认各自有效，具体见 [工具授权](/guide/permissions)；提示词内容与开关本身不能授予工具权限或扩大任务范围。
