# 插件

「设置 → 插件」集中管理已安装插件和插件发现。插件可以提供[技能](./skills.md)、[子代理](./subagent.md)、AI 工具、页面、动作、模型渠道和外部会话，也可以在你授权后参与文件、终端、备份与系统交互。

## 浏览与管理

页面分为「我的插件」和「发现」：

- **我的插件**：搜索并按启用、停用或异常筛选；上方显示已安装和已启用数量。卡片头部将图标、名称、版本状态与启停开关放在一起，底部并排提供「配置」和「详情」。打开开关会先进入原生信任确认，取消后仍停用；关闭开关会停用插件。声明了配置页的插件可直接配置，未启用时会说明为什么不能打开。
- **发现**：搜索插件或按分类筛选。点卡片只查看介绍，不会下载；点「获取」或「更新」才下载并进入安装预览。已安装且没有已知更新时显示「管理」；未固定版本的来源，可在介绍中主动「下载并预览」最新发布包，不把未知版本标成确定有更新。获取／管理按钮与插件名称放在同一行，下载、取消、错误和重试显示在对应卡片中，不把单个插件失败当作整个来源失败。简短错误旁可展开完整原因和诊断信息。
- **顶部「＋」**：从手机 ZIP 导入，或从本机开发目录侧载。两个入口都先预览，不会直接启用。
- **顶部「管理」**：修改来源与下载镜像、集中查看插件权限、清除已记住的操作授权，以及刷新列表。修改来源和权限不会自动批准后续操作。

打开详情时，插件身份、启停与「打开配置」集中在同一张卡片。权限行显示是否已允许，点未允许的能力进入原生授权确认；点已允许的能力查看范围或明确撤销。Android 系统权限仍在独立入口管理。运行准备和页面／动作保持独立分区，功能声明、技术信息与维护操作按需展开，已记住的操作授权可在维护中清除。安全说明可从简短提示打开全文，不改变启用时的信任确认。卸载仍需单独确认，默认保留插件私有数据。普通返回会保留当前入口、搜索、筛选和滚动位置，关闭插件配置页也不会重新开始浏览。成功安装或替换包后会回到未筛选的「我的插件」，避免新装的停用插件被旧搜索或“已启用”筛选藏起来。

插件名称与简介会优先使用发布者提供的对应语言。应用选择中文时，商店与已安装列表会识别简体中文的地区标记；发布者没有提供该语言时才显示原文。不会在线翻译插件内容，也不需要为了切换名称语言重新安装插件；插件自行编写的页面仍由发布者提供翻译。

## 安装、更新与信任

可以从「发现」下载安装包、从手机选择 ZIP，或从本机开发目录侧载。无论哪种来源，都先进入原生安装预览：先核对插件、版本、声明的作者和仓库、来源及重要风险，再按需展开完整功能声明与内容摘要。安装／取消按钮保留在面板底部，不需要滚过整段技术信息才能操作；宽屏设备使用自适应居中面板。

商店内标为上游社区来源的内容不代表阿九审核或认证。名称、作者文字和仓库地址由发布者声明，摘要用于辨认内容是否变化，不能证明作者身份或代码安全。发现同名插件来自不同来源、仓库改变或内容与预览不符时，应停止更新并核实，而不是沿用旧信任。

新装、替换和同版本重装都默认停用。安装预览和安装本身不执行外来脚本；安装成功会回到「我的插件」，确认信任当前内容后再打开启用开关。更新包要重新确认，旧页面和旧操作批准不能沿用到新安装。

::: warning 插件不是进程沙箱
Node.js / Python 插件在**手机本地所选运行时**中作为真实进程运行；默认是 PRoot。使用新建 v2 CHROOT 时，插件进程是 **guest UID 0（guest root）**，guest rootfs 可写，能修改 guest 软件包及容器可见文件，并可能改变共享工作区的文件属主。CHROOT 不提供 PID／user namespace 隔离；普通软件包维护使用受限 capabilities，不授予 `CAP_SYS_ADMIN`／`CAP_SYS_PTRACE`，但这不等于安全沙箱，也不能靠递归 `chown` 自动修复副作用。即使工作区连的是 SSH，也不会把插件自动移到服务器。脚本能直接联网和启动子进程；页面限制、宿主能力开关和弹窗只能约束通过 App 接口发起的操作，不能拦住脚本自己的系统调用，也不保证检测动态或交互脚本的危险行为。来源不明或无法判断代码是否可信时，请保持停用。
:::

## 授权与“始终允许”

启用确认不等于授予所有宿主能力。请求到达时，原生界面显示插件、操作和目标，你可以选择：

- **拒绝**：本次不执行；返回或关闭也不会放行。
- **仅本次允许**：只批准正在展示的这一项。
- **本会话始终允许**：仅在发起请求的同一聊天、同一插件安装内容及启用状态、同一来源内，记住完全相同的操作和参数。其它聊天与子代理不继承。
- **本次插件运行始终允许**：没有聊天上下文的页面或后台调用使用此选项，仅供当前运行及其派生调用使用，不能沿用到下一次独立运行。
- **始终允许**：在该插件当前安装内容、所确认的操作和目标范围内记住决定。命令不因为名称相同就涵盖另一条命令，工作区或服务端改变也不能沿用旧来源执行。

两种会话允许都只保存在内存中，App 进程重启即清除；切换工作区、配置、远端连接或真实通道身份后也需重新审批。不能确认会话或执行来源时，会话按钮不可用并显示原因，可重新发起请求或仅允许本次。原有「始终允许」仍持久保存，并不等同于会话允许。

记住决定后，禁止规则仍会重新检查。修改包、停用、重装或撤销授权会使旧权限失效；可在插件管理中清除已记住的操作授权。插件页面、脚本文字和返回值不能替你点击批准，也不能调用审批接口自行放行。

CHROOT 来源仍绑定插件当前安装内容摘要、激活代际、工作区、实例与 Root 代际，不能借用聊天、其它插件或用户终端的捕获。普通运行时操作默认放行，冷启动由内部自动绑定，避免切换工作区后错写，无需用户逐来源授权；这不取消插件当前内容的信任启用、宿主能力与具体操作授权。实际操作可按需建立 Root 通道，仍核验 Root 总开关、真实系统 su 授权及 App 控制端身份。更新、停用、换源、Root 通道失效或 App 重启后，旧捕获不能继续使用；新操作按当前策略重新绑定，当前来源、Root 身份、实例身份或运行记录无法核验时拒绝执行，不自动重放旧动作。单条历史任务 UNKNOWN 保留诊断但不单独阻止新任务。guest root 可维护 guest 软件包；hostRO 宿主配置、DNS 等绑定仍只读，guest 自己的 `/etc`、`/usr`、`/var` 不等于宿主系统文件。

**桥 API 不授予宿主 Root，不等于插件进程没有 guest root。** 插件 `tools.execute` 仍禁止调用独立 `Root` 和 `Shizuku` 工具；插件专用 Shizuku 操作仍只开放 ADB shell，需真实系统授权、插件能力和相应操作授权，不能借用聊天的单次批准、会话 grant 或内部许可。CHROOT 的正常容器操作默认放行，不因脚本未知、动态路径或交互输入本身自动审批；仅可识别的 Android 宿主系统／共享内核路径修改，或有具体宿主路径线索但行为不明确时先审批。内置 Root／Shizuku 直接作用于宿主，可确认只读默认放行，修改或无法确认是否只读的未知脚本、动态／交互行为先审批。仅本次允许只批当前请求；本会话始终允许覆盖本聊天 session、同一 tool、同一 source／identity 的全部后续宿主修改与不确定操作，包括不同命令和目标，不限当前命令，不跨工具、来源、身份或其他会话，更不让插件继承聊天授权。新宽授权仅存内存，进程重启或来源／身份／Root 代际／Profile 配置内容或选择／实例变化后需重审；每次 Root／Shizuku 执行仍消费完整命令绑定的单次内部 permit。判断只是有限静态识别，不执行或打开脚本、不推导拼接路径；Root／Shizuku 中实际只读脚本也可能弹窗。符号链接、`PATH` 和任意程序的实际副作用不能保证，不是运行时拦截、无限 OS Root 权限或插件进程沙箱。独立计划审批每次都由你本人决定，没有「始终允许」，脚本不能代批。插件声明或能力开关不能代替显式禁止、Root 总开关、真实 OS 授权、命令检查、当前 CHROOT 来源、实例身份和清理核验、依赖准备、独立实例创建／停止／移除及共享／不可逆操作确认；单条历史任务 UNKNOWN 保留诊断但不单独阻止新任务，异常实例删除在核验通过后无需重启；PRoot／SSH 的原有 `sudo`／高危提权及完整精确命令授权策略也不取消。相关边界见[工具授权](./permissions.md)。

模型访问、备份、浮层、自启动和请求改写等能力，在插件详情中有独立的用途和授权。只开启实际需要的项目；允许使用模型可能产生供应商费用，允许备份扩展可能暴露你选中的备份数据。

## 页面、动作与工作区工具

插件详情可以打开配置页、包内页面与声明的动作。声明了对应位置的插件，还会出现在设置分组、聊天菜单、欢迎页、侧栏、文件树或编辑器选区菜单；工作区工具可以加入项目工具面板。切换项目时，工具选择随项目变化，不把旧项目动作交给新项目执行。

聊天页三点菜单中的「项目工具」会打开居中的圆角浮层，四周保留留白，不再使用贴边全高抽屉。普通屏幕下默认约 438dp 高，短屏会自动缩小，长列表在浮层内滚动。可切换「全部工具」查看已启用插件提供的工作区工具，并固定到当前项目；没有可用工具时显示空状态。点「关闭」、遮罩或系统返回键关闭面板，不会触发工具。打开具体插件页面后的显示与能力授权保持不变。

页面只接受自身受限来源的主框架消息；不加载远程页面资源或嵌入框架。为兼容包内 Vue 模板，已信任的本地页面允许所需的脚本编译，这不代表页面可以任意访问宿主。WebView 缺少安全消息桥或文档启动脚本功能时，页面会显示错误，不回退到旧的 JavaScript 接口。

浮层还需要你在 Android 系统设置中授予悬浮窗权限。可设置显示策略、尺寸和位置；息屏或不满足显示条件时暂停展示。停用或撤权后关闭插件自己的浮层。系统省电、前台服务和通知限制可能影响后台运行，不保证永久常驻。

## 文件、终端与端口

**脚本运行在哪，与它请求 App 操作哪个环境，是两回事。** 例如插件进程仍在手机，但一次经你批准的文件读取可以指向当前 SSH 工作区。

文件接口支持读取、二进制、列表、写入、追加、目录创建、复制、重命名、删除和页面文件订阅。作用范围依据捕获的执行环境及已授权根确定；工作区、本机授权目录和插件私有数据不能用旧路径或另一后端的同名路径替换。复制与覆盖先核实源、目标及冲突，读取和递归都有大小、数量与深度限制；访问根目录、祖先或重叠范围的危险操作会被拒绝。App 私有管理文件和插件依赖控制区不因普通文件授权而开放。

插件创建的终端和端口资源有插件归属：停止或关闭自己的资源不应关闭你手工创建的终端或其他插件的连接。SSH 端口映射只使用回环地址，不能将任意服务监听到手机的公开网络接口。常规操作仍可从[文件页](./files.md)、[终端](./terminal.md)和[浏览器端口映射](./browser.md)进入。

## 会话、模型与扩展事件

插件可在授权范围内读取或管理普通会话，提供外部会话列表与流式消息，或通过已配置的提供商调用模型。外部会话属于插件自己的来源，不与本地聊天 ID 混用。插件提供商只维护其声明的渠道，不能借相同名称覆盖用户渠道；已有密钥不会直接返回给插件。插件自己的秘密存储与其他插件隔离并加密落盘。

生命周期事件可用于观察运行、请求、工具、压缩以及插件启停。可写事件能修改工具参数、成功结果或模型 HTTP 请求；修改后的工具参数仍要重新检查权限。请求头中的宿主敏感凭据会脱敏，改到另一目标时不沿用原渠道凭据。事件返回“允许”不等于用户批准；三模式和插件代审批没有恢复。

自启动需独立授权。后台插件只能使用其仍然有效的来源和能力；后台消息不能把已经失效的工作区授权变成当前项目的许可。界面重建或网络重连不会自动重放有副作用的动作。

## 完整备份与还原

在「设置 → 备份与还原」勾选**插件**，可保存已安装插件的安装内容、插件配置页等保存到私有数据中的配置与文件，以及可迁移的插件密钥。首次默认关闭，之后记住勾选状态；不要求插件为此启用，完整备份与还原本身不执行其安装、清理或备份扩展脚本。安装文件会重新打包，保留内容，但不保证与最初下载的 ZIP 逐字节相同。宿主管理的依赖和备份导入、导出缓存不包含在内。

**插件提供商账户与 API Key 仍由「AI 供应商」选项控制**，不是勾选「插件」就包含；浮层位置和插件市场全局偏好也不在完整插件备份范围内。插件密钥会受控解密后写入备份，还原时用目标设备的系统密钥库重新加密。本地导出请优先设置口令；留空时备份中的密钥可被直接读取，网络上传则必须加密。

还原预览中完整插件默认不选，覆盖默认关闭；已有相同插件 ID 时会整项报告冲突，明确打开覆盖后才一起恢复安装内容、私有数据和密钥。请先备份当前数据并停止插件动作。恢复后视为新安装且保持停用，不继承信任、能力或操作授权、真实系统 Root／Shizuku 授权、内部执行许可、来源捕获、其他适用的会话授权、自启动许可、运行状态及已安装依赖；需你重新审阅、启用并按需准备依赖。安装内容、数据和密钥不是跨三类存储的一次性事务，出现「部分还原」时先按报告核对已成功部分，不能假定全部回滚。操作流程见[备份与还原](./backup.md#导入)。

## 备份扩展

原有**插件扩展数据**与上方完整插件备份独立。在[备份与还原](./backup.md)中另选要参与的扩展区段：插件必须已安装、启用、声明用途并取得备份能力授权；勾选区段本身不是授权。只有明确选中且满足授权时，才可运行插件声明的相应备份或还原处理，不会为了备份临时启用插件。还原预览可以再次选择区段，未选择、不可用、拒绝和失败分别显示结果，不把没有还原的插件数据算作成功。

扩展区段本身不会安装或启用插件、恢复历史审批或启动待执行任务。选择同一插件的完整还原时，其扩展还原会被取消选择并跳过，不能同时执行两种方式；未选择的扩展也不会自动执行。没有安装对应插件时仍可先恢复主数据，再自行决定是否选择完整插件还原。

## 运行环境与开发

纯技能正文无需为了阅读而安装解释器。需要进程时，手机本地容器应已有 Node.js 或 Python 3；在 SSH 服务器上安装解释器不能解决手机端缺失。App 不会为了启动插件偷偷安装系统软件；新建 v2 CHROOT 可在明确任务范围内通过 `apt` 等工具准备 guest 软件包，这与插件依赖准备及内容启用确认分开处理。

声明了依赖的插件还需单独确认准备。npm 以包根的 `package.json` 和可选锁文件准备执行副本，保持 CommonJS／ES 模块与依赖的相对布局；pip 使用插件私有的 Python 依赖目录。默认目标私有不代表安装脚本只能写那里，第三方代码仍具有受信任进程的风险。准备失败、缺少解释器或输入改变时，先核实环境，不把失败当作动作已经完成。

源码仓库提供 SDK、TypeScript／Vue 模板、示例、清单校验与打包工具。按模板的锁文件构建，并使用与本版匹配的方法声明；不要用脚本自行伪造用户审批。修改后的插件先侧载审阅，在测试环境验证，再用于真实项目。

## 停用与排错

- **商店提示找不到对应版本的发布包**：在「发现」刷新索引，再核对发布页是否提供该插件、该版本的 ZIP。商店支持上游及本地插件的两种常用文件命名；索引指定了版本时，不会擅自安装另一个版本。也可下载发布者的 ZIP，从顶部「＋ → 从本地 ZIP 导入」进入同样的原生预览；不要选择仓库自动生成的源码压缩包。
- **下载失败**：检查网络、来源和设置的下载镜像后重试。这与“找不到对应版本的发布包”不同；修改系统安装权限或卸载 App 不能解决发布文件缺失。
- **导入拒绝**：检查 ZIP 根清单、引用文件、版本范围、路径、重复条目和包大小。不要为了绕过拒绝改用另一条宿主路径。
- **旧页面失效**：关闭后重新打开，确认当前插件版本、工作区和授权。未知副作用先核实，不盲目重试。
- **提示尚未授权系统浮层**：关闭桌宠或插件配置页，进入「设置 → 插件 → 我的插件」，打开该插件详情，在「权限与授权」中点「系统浮层」并由你确认授权，再重新打开配置页重试。这是插件能力授权，和 Android 系统权限是两项独立许可。
- **提示系统悬浮窗权限未开启**：在插件详情点「打开系统悬浮窗授权设置」，允许阿九工作台显示在其他应用上层后重试。不能只在插件自己的配置页点“显示”来代替这项系统授权。
- **缺少其他能力**：到插件详情审阅用途，再由你决定是否授予；脚本不能自授。宿主内置错误提示随应用语言显示，错误码保留用于排查；插件自行编写的页面文案和任意脚本错误不一定提供中文。
- **后台或浮层没出现**：检查插件能力、Android 悬浮窗／通知权限和系统后台限制；“常驻”不等于永久存活。
- **停用或卸载**：停用阻止后续调用并清理自有资源，但不能撤销已经发生的文件或网络副作用。卸载默认保留私有数据，确认不再需要时再选择删除。
