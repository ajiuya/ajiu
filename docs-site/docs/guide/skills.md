# 技能

技能是为 AI 提供的「专项能力扩展包」——把某类任务的标准流程、最佳实践与专属知识沉淀为规范指南，AI 遇到相关任务时会自动按需加载执行，无需你在每次对话中反复交代背景规则。

入口在「设置 → 技能」。已启用的技能会出现在对话输入框的 `/` 菜单里，可以直接用 `/技能名` 触发，也可以带参数（如 `/pdf-report a4`），详见[对话与消息](./chat.md)的〈斜杠命令〉。

## 内置编程技能

App 随包提供适配后的 **dev-god（编程大神）**，上游为 [SkillHub 的 @ake/dev-god](https://skillhub.cn/skills/ake/dev-god)，本次内置基于 1.2.4。它用于复杂工程接管、实现、调试、代码审查和验证；配套参考资料与可选工程探测脚本随包提供，按任务需要加载，不会每次把整套资料全部加入对话。

在「设置 → 技能」可查看或停用，也可在新会话输入 `/dev-god` 并附上任务要求。安装或重新启用后，新开会话刷新可用清单。已有同名技能保留，不自动覆盖；删除后的内置技能不会在下次启动复活。

内置技能仅提供工作指导，不安装全局 SkillHub CLI、不改变首选技能源、不自动更新或执行脚本。可选脚本需要目标环境已有 Python；不为运行它自动安装依赖。涉及依赖安装、外部状态、计划、高危工具及发布时，仍遵守 App 的对应授权要求；你明确要求先不构建时，技能也不能擅自打包或发布。

上游包未附统一的独立许可证，部分资料另有来源声明，内置版本保留这些说明和原始出处；不将其声明为新的开源许可。

## 技能从哪里来

一个技能就是一个目录，其中有 `SKILL.md`（或兼容的 `CLAUDE.md`）即会被自动识别。分两级：

- **全局技能**：放在 `~/.aicode/skills/`，跨项目共享，App 升级不丢失。跟随执行环境：本地模式下是容器内 `/root/.aicode/skills/`（映射至手机 App 私有目录），远程模式下指**服务器**上的 `~/.aicode/skills/`，读写经由 SSH 完成。
- **项目级技能**：放在 `<工作区>/.aicode/skills/`，只在当前工作区生效，可以随项目提交到 git。远程模式下这里指的是**服务器上**的工作区，读写经由 SSH 完成。

同名技能项目级优先。

本地选择 CHROOT 时，菜单和设置页从 App 私有全局目录、当前项目固定技能目录及对应的 `skills.json` 读取定义快照，不需要先创建实例或建立 Root 通道。定义快照包含技能正文，但读取菜单不会启动实例或执行脚本；实际任务、文件操作与命令仍核验当前来源、文件范围和运行状态。普通 CHROOT 来源按策略绑定，无需逐来源设置授权；能确认宿主操作只读时默认放行，修改宿主或未知脚本、动态路径等无法确认是否只读时先审批，实际只读脚本也可能弹窗。可仅本次或本聊天会话允许同一工具、同一来源及身份的全部后续宿主修改与不确定操作，包括不同命令和目标，不限当前命令，不跨工具、来源、身份或其他会话。新的宽 grant 仅存内存，进程重启或来源／身份／Root 代际／Profile 配置内容或选择／实例变化后需重审；每次 Root／Shizuku 执行仍使用完整命令绑定的单次内部 permit。有限静态识别不是运行时拦截或沙箱；技能和会话授权不扩大任务范围，不覆盖显式禁止、真实 OS 授权或 CHROOT UNKNOWN／清理限制，也不替代独立计划、插件信任及实例操作确认，详见[工具授权](/guide/permissions)。PRoot 的路径解释及 SSH 的远端技能源保持各自语义，不会因为菜单读取失败而改读另一套目录。

CHROOT 定义来源不跟随未支持的链接，也不把来源失效、启停文件损坏或读取错误当作「所有技能启用」。切换项目、模式或容器配置后，旧来源的菜单和正文不能继续使用；修复来源后重新刷新可恢复。技能正文编辑、导入和删除仍受原文件后端及权限约束，不因查看菜单获得额外宿主路径访问能力。

你可以直接在 App 里新建技能（见下文），也可以在容器里手工创建技能目录，或交由 AI 从 GitHub 安装。本地模式下 App 会监听技能目录，手工添加、删除、改名后列表几秒内自动刷新，无需重进页面。远程模式下不会监听服务器上的文件变化，手工修改后需退出并重新进入设置页刷新列表。远端定义采用批量校验和短期内存缓存，未变化的正文不会逐个重复下载；重新进入页面会重新核验，App 内保存或删除后会使相关缓存失效。缓存不写成另一份技能目录，重启后重新读取；切换服务器、工作区或容器配置不会沿用原环境的菜单内容。

AI 对话中的可用技能清单在会话开始时生成。安装或启用新技能后，新开会话即可让 AI 使用更新后的清单。实际加载技能时会重新核验当前环境的定义，不把旧服务器的菜单当作当前可执行内容；连接中断或来源已切换时需等待当前环境就绪后重试。

## 列表页

按「当前项目 / 全局」两个可折叠分组显示，点分组标题展开或收起。

每行是一个技能：图标、名称、描述摘要，名称右侧的彩色勋章表示启用或禁用状态。点行进详情；左滑露出删除按钮，删除会弹确认框——它会直接移除技能目录，**不可恢复**。

右上角「＋」添加技能（见下文〈添加技能〉）。

### 批量操作

列表右上角的「多选」按钮（方框带勾的图标）可以一次处理多个技能：

1. 点「多选」进入多选模式，每行左侧出现勾选框，整行点击即勾选；两个分组共用一份选中集合。
2. 顶部操作条提供「启用 / 停用 / 删除」与「全选 / 取消全选」，最右「×」或系统返回键退出多选。
3. 「全选」包含折叠起来的那个分组，不会因为分组收起而漏选。
4. 删除会弹确认框；确认后逐条删除并显示「正在删除…」，删完列表自动刷新并退出多选。远程模式下每条技能都要经 SSH 递归删除，条目多时会慢一些，请等提示消失再离开页面。

多选模式下不能点击进入详情页，也不能左滑删除单条。

## 添加技能

点右上角「＋」弹出底部选择单，先选**作用域**（全局 / 当前项目，默认全局），再选添加方式：

- **手动新建**：进入编辑页，填写名称、描述与正文，从头创建一个技能。
- **从文件导入**：选择一个 `.md` 文件（`.markdown` / `.txt` 也可）。App 读取文件内容，按其 frontmatter 的 `name`/`description` 建技能，缺 `name` 时用文件名兜底，写入 `<作用域>/skills/<名称>/SKILL.md`。
- **从压缩包导入**：选择一个 `.zip`。App 解压后识别包内所有含 `SKILL.md`（或 `CLAUDE.md`）的目录，逐个导入——一个包可以包含多个技能，常见于 GitHub 仓库的打包下载。

导入与手动新建等价：文件一律归一化为 `SKILL.md` 落盘，之后同样可以用编辑器或容器命令修改。

**几种会被跳过的情况**（会弹窗逐个列出原因，不影响其余技能）：

- 技能名称不合法（含 `/` `:` 等不能做目录名的字符、为空或过长）；
- 目标作用域下已有同名技能（不会覆盖）；
- 技能正文为空；
- 压缩包里没有任何含 `SKILL.md` 的目录（整体失败）。

## 详情页

三张卡片：「是否启用」（名称、来源和启停开关）、「摘要」（描述）、「正文」（`SKILL.md` 的完整内容，等宽字体，可以选中复制）。

右上角的铅笔按钮进入编辑页。

## 新建与编辑

编辑页有两组内容：

- **基本信息**：名称、描述、作用域。名称就是 AI 加载技能时使用的标识，建议使用英文小写加连字符（如 `pdf-report`）；描述写明「何时该使用它」，AI 依据这句话判断是否需要加载；作用域选「当前项目」或「全局」，决定技能目录落在哪一级。
- **指令正文**：技能的完整指令，支持 Markdown。写清这类任务的标准流程、约束与注意事项。

软键盘弹出时，编辑区域会避让键盘；正文较长时可以上下滚动，继续编辑末尾内容。

名称和正文都填写后才能点击右上角「保存」。保存后会写成 `<技能目录>/SKILL.md`，与手写的技能完全等价，之后同样可以用文本编辑器或容器命令修改。

几个需要留意的地方：

- **作用域只能在新建时选**。已有技能的作用域是灰的——更换作用域等于搬迁目录，需要自行在容器里移动。
- **改名只改 `SKILL.md` 里的 `name`，不动目录名**。技能正文里常按 `~/.aicode/skills/<目录>/run.py` 引用同目录脚本，目录跟着改名会把这些引用打断。
- 编辑的是从 GitHub 装来的技能时，如果它用的是 `CLAUDE.md` 而不是 `SKILL.md`，保存会写回原来那个文件，不会多出一份。
- 同一作用域下已有同名技能、名称含 `/` `:` 等不能做目录名的字符、或正文为空时，保存会失败并在页面顶部给出红色提示。

## 启用与禁用

详情页的开关控制该技能是否参与 AI 会话。禁用后它不再出现在系统提示的可用技能清单里，AI 也无法加载，可减少上下文占用——技能数量较多时这个开关很有用。

禁用名单写在 `skills.json` 里：全局名单位于当前执行环境的 `~/.aicode/skills.json`，本地模式保存在手机 App 私有目录，远程模式保存在服务器上；两者独立，不会自动迁移或同步。项目级名单在本地模式位于 `<工作区>/.aicode/skills.json`，远程模式仍保存在手机 App 私有目录，按服务器和工作区隔离。格式是：

```json
{ "disabled": ["技能名"] }
```

两级取并集，任一作用域禁用即生效。也可以直接手工编辑名单，下次读取时生效；本地模式下列表几秒内自动刷新，远程模式下手工修改服务器上的名单后需退出并重新进入设置页刷新列表。

## 备份与迁移

在「设置 → 备份与还原」单独勾选**技能**，会保存完整技能目录，包括定义、配套脚本、资源、参考资料和相应的 `skills.json` 启停配置；不会只保存正文，也不会因技能名称与内置技能相同而漏掉你的修改。已安装依赖、虚拟环境、Git 目录及缓存不在此范围内。该选项首次默认关闭，之后记住勾选状态，与记忆、提示词和插件分别选择。

范围包括手机侧全局与已登记本地项目，以及**当前已连接 SSH 的全局和当前项目**技能，不遍历所有保存的服务器。需要备份远端技能时先连接服务器并选中远程工作区；远程全局启停配置在服务器上，项目启停配置仍随手机保存的对应远程项目配置备份。

还原预览按来源、位置和项目选择，默认不选且不覆盖同名文件；覆盖只替换所选范围中的同名文件，不清空其他技能。还原到 SSH 前还需核对当前目标并明确确认，断开或切换环境后不能沿用旧确认，也不会改存手机。恢复技能不运行脚本、不安装依赖，也不代你批准工具或 Root 请求；核对内容后新开会话刷新可用清单，详见[备份与还原](./backup.md)。
