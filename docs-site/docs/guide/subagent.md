# 子代理

::: tip 版本说明
子代理从 1.11.0 起提供。
:::

子代理是由主会话派生出的独立工作会话。当你面临耗时较长的调研、多模块并行审查或架构对比等复杂任务时，可以让 AI 派发子代理并行处理，**不阻塞当前主对话**。

子代理拥有自己独立的上下文与工具能力。派发后它会在后台独立工作，你可以留在主会话继续讨论，也能随时点进子会话查看实时进度、补充提问或手动暂停。

有合适的子代理且部分工作可以独立完成时，AI 会主动分发这部分任务，同时继续推进主线，负责协调、核验和整合结果。简单或紧密耦合的任务由主会话直接完成，不必把所有工作都派给子代理。

子代理分为两种：
- **默认通用子代理**：自动继承父会话的模型配置与全部可用工具；
- **自定义子代理**：支持自由指定模型、工具白名单/黑名单以及专属提示词。

## 内置子代理

首次使用时提供五种中文命名的专职代理，可在「设置 → 子代理」查看能力与启停：

| 名称 | 主要职责 |
| --- | --- |
| 探索员 | 只读定位代码、调用链和影响面 |
| 编码员 | 在指定任务范围内实现功能、修复问题 |
| 审核员 | 只读检查正确性、安全风险与遗漏 |
| 测试员 | 编写回归、执行已授权的测试并报告证据 |
| 架构师 | 只读分析技术方案、模块边界与取舍 |

它们不绑定供应商或模型，按当前配置继承或使用指定档位。写文件、运行命令等能力取决于每个定义的工具清单；所有代理仍遵守禁止规则和高危操作审批，不能继续嵌套派发。角色名称不是额外授权。

内置定义只首次提供，不会覆盖已有同名文件或同名自定义代理，也不会在你删除后于下次启动自动恢复。项目级定义仍可覆盖同名全局定义。旧的自定义 Explore 和历史会话名称保持原样，不为统一新默认名称而改写；新默认名单使用「探索员」。本地与 SSH 环境分别接收内置资产，不会将手机上的自定义配置上传到服务器。

## 使用方法

在主会话中直接向 AI 提出派发需求即可，例如：

- 「派个子代理去审查 `app/build.gradle.kts`，把潜在问题列出来」
- 「同时派两个子代理，一个调研数据库迁移方案，一个调研 UI 组件库选型」
- 「派一个只读调研子代理查清当前的登录与鉴权流程」

在任务范围内派发子代理属于普通工具调用，默认自动放行；若项目或全局规则禁止派发工具，则不会启动。子代理启动后在后台工作，主会话可继续接收你的其它指令；派发不代表它获得了超出任务范围的授权。

## 主会话中的协作卡片

主会话把子代理任务按**你实际发送消息的轮次**归为「子代理协作」分组。分组默认收起，先显示状态概览与参与者的真实名称摘要；点开后可以查看该轮涉及的全部子代理，没有固定只显示 3 张或 5 张的限制。**最多同时运行 5 个**是并发限制，不是卡片数量限制。

- **同轮合并，跨轮保留**：同一轮内，对同一个子代理的派发与反复追加指令合为一张卡片，对应最后一次真实派发或发送；后续轮次再次实际向它发送指令时，可以在新一轮另有卡片。后台进度或完成提醒只更新对应任务，不凭空生成新卡片或新的一轮。
- **留在所属轮次**：已结束轮次的分组放在该轮正文、工具等普通内容之后、下一条用户消息之前。主会话当前仍在工作时，本轮分组位于实时正文与思考之后；旧轮子代理即使仍在运行，也留在旧轮，不会搬到新一轮下面。
- **按状态稳定排列**：已完成的任务在前；失败、中断、已删除与仅有历史记录的任务居中；排队、执行中与等待确认的任务在后。同一类内保持原顺序，不会只因输出更新或计时变化而来回跳动。

### 查看交互与执行过程

每张子代理卡片也默认收起，使用紧凑列表，以**实际派发的代理名称为主标题、任务描述为次行**；状态与展开入口放在右侧，下方显示真实当前动作或最近公开摘要，以及往返次数、工具调用数和已记录耗时。点开某一项即可阅读详情，其他子代理仍保留各自摘要，便于对照多个任务。名称与任务分开：例如实际选用的配置名是「编码员」「审核员」或 Explore，就原样显示对应名称，不根据任务描述或模型推测角色。分组中的名称摘要过长时省略显示，展开后仍可查看该轮全部子代理，不影响数量或排序；侧边栏展开后的子会话列表也显示名称和任务。

历史子会话缺少名称时，仅在有可靠的成功派发记录时恢复显示，否则提示「名称未记录」；未指定命名代理的普通子任务显示「子代理」。删除子会话后，能够从原成功派发记录恢复的名称仍可用于只读展示，不会因此重新启用或运行代理。没有记录的耗时显示为未知，不拿旧回复的时间补算。

点卡头展开后，可以分别查看：

- **交互记录**：区分主代理、子代理和你发送的消息，用「较早 / 较新」翻页；需要时继续加载更早记录。
- **执行过程**：独立展开，查看子代理的公开回复和工具执行记录；展开交互记录不会自动打开执行过程或所有工具详情，也不会重跑任务。长内容可以分段、分页阅读，卡片不展示子代理的私有思考内容。
- **进入子会话**：切换到对应会话继续查看或对话；长按卡头也可直接进入。
- **停止子代理**：停止对应子任务，不会代替你停止其他子代理或主会话。
- **等待确认**：从提示入口进入对应子会话，阅读完整工具授权或计划请求后再决定；主会话卡片只提供进入入口，**不提供快捷批准**。

子代理从排队、执行中或等待确认转为完成、失败、中断或删除时，该子卡片会自动收起，之后可以手动重新打开；这不会强行收起整个协作分组。已结束卡片重新打开后，不会仅因摘要刷新再次自动合上。

只有卡片展开且聊天界面在前台可见时，才加载、刷新对应记录正文；收起卡片、离开页面或切到后台后停止这部分加载，不因此停止真实任务。

### 在主会话补充指令

展开卡片，在「补充指令」输入框写明要求并发送，**只发送给这一张卡片对应的子代理**，不占用或覆盖主会话草稿。

这是一条发给子会话的正常用户消息，不是后台代理通知：子代理忙碌时进入它自己的用户消息队列，空闲时可开始下一轮。以 `/` 开头的内容也作为普通正文交给子代理，不会在主会话执行斜杠命令。

卡片发送的补充指令可以在子会话队列中**拖拽排序或删除**，但不能再编辑或「立即插入」，对应按钮不可用；要改内容，请先删掉旧条目，再重新发送，以保留每次实际发送的原文。删除排队指令，或停止全部任务时清空队列，会保留取消记录，不算作已执行，也不阻止子代理之后正常处理新的请求。

查看卡片、翻页或重开历史本身都不会发送消息。请在发送前核对任务和子会话；目标已删除、不属于当前主会话或工作区不一致时不能发送，不会转发给其他会话。

补充指令不代替工具授权或计划审批，也不能绕过已经拒绝的计划。等待确认时，请进入子会话按原审批流程处理。

### 历史、重启与删除

已记录的派发、双方消息、排队指令取消、完成、失败、停止、中断和删除信息会保留在主会话的交互记录中。进程结束前尚未收尾的执行，重启后会依据保存的运行记录标为中断；待处理结果通知会等待你确认，不会自动请求模型。已有终态不会被改成中断，展示名称优先保留当时已记录的实际代理名称。删除某个子会话后，主会话仍可显示「已删除」及已保存的往来，但不能再进入、停止或向它发指令；删除主会话则一并清理其子会话与所属交互记录。

旧聊天没有完整交互记录时，只展示能从已有历史恢复的内容，不补造状态或输出，也不自动执行旧指令。是否已经处理按每条实际请求分别记录，调整队列顺序不会把仍未运行的请求算成已执行；若你发给子代理的指令尚在排队、还未真正开始，重启后会显示为中断，**不会自动重放**。已取消的指令不会再等待执行；本机会话已有恢复卡时，可进入子会话审阅后继续，否则请主动重新发送。备份范围与恢复规则见[子代理交互记录备份](/guide/backup#子代理交互记录)。

## 子代理的计划审批

子代理处理复杂、高风险、影响面不明或你要求先规划的任务时，同样要先只读检查并提交完整方案，再等你批准。普通小改不强制审批；父会话已获批准且分配范围未变的方案不必重复提交，但不能把对父会话某一次请求的批准用来处理子会话的新请求。

子代理发起计划审批后，摘要卡和完整审阅面板会显示**该子会话的标题**，侧边栏显示等待审批状态。请核对会话，再点「查看计划」阅读完整内容，选择「批准执行」或填写可选拒绝意见后「拒绝并结束」；不设「始终允许」，后台通知也不能直接批准。

每次请求只归属发起它的会话，主会话、兄弟会话和其他会话互不共用。待审批仅保存在内存，取消时清理，重启后需要重新提交；这与重启后保留的高危工具会话授权不同。与计划提交混在同一批的其他调用均标为未执行，批准后仍需重新发起。

拒绝或没有取得有效批准时，结束的是**发起请求的该子会话本轮**，其持续目标一并暂停，不会自动重提、再答一轮，或由排队消息和后台提醒续跑。若要调整，请在该子会话发送下一条消息要求修改计划后重提，不应通过重新派发或转发消息绕过拒绝。计划批准不扩大任务范围，不覆盖禁止规则，也不替代 Shizuku、root 或高危工具审批，详见[计划审批与工具授权](/guide/permissions#计划审批)。

## 侧边栏中的位置与管理

侧边栏会话列表清晰展示了主会话与子代理的父子归属关系：

- **展开与收起**：派生过子代理的会话，行尾会显示子代理数量与展开折叠箭头。点击箭头可展开查看其下属的所有子代理；
- **状态指示**：正在运行中的子代理会显示绿色的运行状态指示灯；
- **独立交互**：点击子代理即可切换进入其会话页，界面与常规会话完全一致，可独立对话、暂停或重新生成；
- **会话操作**：长按子代理项可进行重命名、导出与删除；删除子会话不清除主会话已保存的交互记录，卡片改为已删除。删除主会话时，其名下的所有子代理及所属交互记录会随之一同清理。

## 上下文与信息传递

::: tip 上下文独立与双向同步
子代理拥有独立上下文，默认通过派发说明获取主会话的任务背景，保证轻量与专注：

- **任务派发**：AI 在派发子代理时，会提炼明确目标与完成标准、关键文件路径、已核实的背景、用户约束、可改动的范围以及期望产出，打包作为初始指令交给子代理。如果你在主会话中手动指示派发，也建议交代清楚关键背景与期望产出；
- **结果汇总**：子代理的最终报告应完整写明结论、依据、改动文件、验证结果与未完成项，让主会话仅凭最终报告即可理解结果。子代理正常完成后，主会话会自动收到完成通知，通知里**直接带上结果摘要与本次改动过的文件**，主会话按摘要为你汇总；需要完整报告或核对细节时才会再读取一次子代理的最终产出。主会话正在工作时，提醒由当前操作承接，不会因此另造用户轮次；计划被拒绝或未获有效批准时仍不得自动续跑。
- **公开记录追溯**：在主会话展开协作卡片，可查看已记录的往来与独立的执行过程；需要在完整子会话中继续查看、对话或处理确认时，使用「进入子会话」或侧边栏入口。主会话卡片不展示子代理私有思考。
- **派发提示与告警**：能够明确匹配到本主会话任务、且派发成功的信息会由交互卡片承接，避免重复显示旧派发提示；失败、无法识别、部分成功或带警告的提示仍保留，不能把有卡片当作所有任务都已成功。
:::

## 与主会话的双向通讯

子代理与主会话之间支持双向异步通讯，互不阻塞：

- **主会话 → 子代理**：主会话可以在已授权的任务范围内向子代理追加消息（补充指令、调整分工、纠偏，或对已有结果继续追问），**可反复发送**。运行中的子代理会在下一轮操作里收到该消息；已完成或暂停的子代理会被重新唤醒并继续工作；
- **子代理 → 主会话**：子代理在运行中可以主动向主会话汇报关键进展、求助，或提交需要协调、决策的事项。主会话会收到一条系统通知，并可直接回复。

主会话与子代理的真实往来可在卡片的「交互记录」中查看；后台通知只是承接和更新这些消息，不会单独新增任务卡片或用户轮次。主会话忙碌时通常在当前操作后处理，空闲时可接续处理提醒，但这不是你又发送了一条消息。你在卡片中填写的「补充指令」则是目标子会话自己的正常用户输入，使用它的用户消息队列，不混作代理通知。

若当前轮因计划被拒绝或未获有效批准而结束，不会用待处理提醒自动续跑；主会话与子代理之间的通讯也不代表用户批准了新计划。

## 自动派发与手动指定

主会话 AI 了解当前所有可用的子代理及其擅长领域：

- **自动匹配**：当你的需求与某个子代理的用途描述（`description`）相符时，AI 会主动选用该专属子代理；
- **手动指定**：你也可以在指令中明确指定，例如「使用探索员子代理检索所有网络请求的入口」。

## 探索员的模型配置

探索员默认继承当前会话的模型。想为它指定更经济的模型，可在「设置 → 子代理」打开探索员并修改模型；也可以编辑全局定义文件 `~/.aicode/agents/探索员.md` 的 `provider` 与 `model`。

若希望 AI 按任务难度挑选模型，在「设置 → 默认模型 → 子代理模型档位」配置轻量、均衡、强力三档。定义里明确指定的模型优先于档位；只改模型不会增加写文件或执行命令权限。已有用户定义和个性化修改在升级时保留。

## 自定义子代理

创建自定义子代理有两种方式，效果完全等价（App 内保存后写出的就是同一份 `.md` 文件）：

- **在 App 内新建**（推荐）：「设置 → 子代理」右上角的「＋」，填表单即可，模型可以直接从已配置的供应商里选；
- **手写定义文件**：自行把 Markdown 文件放进对应目录，适合从其它项目拿现成定义或用 git 管理。

两个可选目录：

- **全局配置**：`~/.aicode/agents/<name>.md`，所有项目共享，升级不丢失。跟随执行环境：本地模式下是容器内 `/root/.aicode/agents/`（映射至手机 App 私有目录），远程模式下指**服务器**上的 `~/.aicode/agents/`，读写经由 SSH 完成；
- **项目级配置**：`<项目工作区>/.aicode/agents/<name>.md`，仅对当前工作区生效，可随代码库一同提交到版本控制中。远程模式下这里指的是**服务器上**的工作区，读写经由 SSH 完成。

同名定义时项目级优先。文件由顶部的 YAML 配置（frontmatter）与正文提示词组成：

```markdown
---
name: researcher
description: 只读代码与技术调研：广泛检索代码、查阅网络资料并汇总结论，不修改文件
provider: DeepSeek
model: deepseek-reasoner
reasoningEffort: high
tools: [readFile, list, search, websearch, webfetch]
disallowedTools: [Bash, terminal]
inject: [base, projectRules]
---
你是资深代码调研专家。请先使用 search 定位入口，再用 readFile 深入核实。
输出结论时请务必标注准确的 `文件路径:行号` 引用；未核实推断需如实注明。
```

### 配置项说明

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `name` | 否 | 子代理标识名称，省略时取文件名 |
| `description` | 建议填写 | 简述适用场景与专长，主会话 AI 依据此描述判断何时选用该子代理 |
| `provider` | 否 | AI 供应商名称，省略时继承父会话配置 |
| `model` | 否 | 模型名称，省略时继承父会话配置 |
| `reasoningEffort` | 否 | 思考强度：`none` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max` |
| `tools` | 否 | 工具白名单。**省略时代表开放全部可用工具** |
| `disallowedTools` | 否 | 工具黑名单，优先级高于白名单，支持 `mcp__*` 前缀通配 |
| `inject` | 否 | 注入的系统规则片段，详见下表 |

### inject 规则片段

| 取值 | 含义 |
| --- | --- |
| `base` | 子代理专用轻量基线：包含工具使用规范与路径约定，轻量且省 token |
| `mainRules` | 完整通用规则：与主会话保持完全一致的行为准则与规则基线 |
| `skills` | 技能支持：注入可用技能清单，允许子代理加载并执行项目技能 |
| `memory` | 记忆支持：注入全局与项目长期记忆摘要，见 [记忆与项目规则](/guide/memory) |
| `projectRules` | 项目规则：注入全局（`~/.aicode`）与工作区内的 `AGENTS.md` 或 `CLAUDE.md` 约束，见 [记忆与项目规则](/guide/memory) |

`base` 与 `mainRules` 是同一套规则的简版与完整版，**正常只选一个**。两个同时开启不会报错，但会把相互重叠的规则文本注入两遍，徒增上下文占用。

若省略 `inject` 字段，默认等同于 `[base, skills, memory, projectRules]`。如果填写 `inject: [none]`，则仅使用你在 Markdown 正文中编写的提示词。

## 在设置中管理

进入「设置 → 子代理」，可以按「当前项目 / 全局」分组浏览所有已识别的子代理。

- **新建**：点右上角的「＋」。表单里可以填名称与用途描述、选作用域（当前项目 / 全局）、从已配置的供应商中**选定模型与思考强度**、勾选工具白名单与黑名单、开关要注入的提示词片段，最后写 agent 提示词正文；
- **编辑**：点击进入某个子代理的详情页，再点右上角的铅笔图标。修改名称会连带重命名它的定义文件；
- **启用 / 禁用**：详情页顶部的开关。禁用后它不再出现在主会话 AI 的可派发清单里，AI 也无法再指名派发它，但定义文件保留，已在运行的子会话也不受影响；
- **能力标注**：主会话看到的可派发清单里，每个子代理后面都标着「文件读取 / 文件修改 / 执行命令」三项能力（由工具白名单、黑名单推导），AI 据此派活——不会把修改任务派给只读子代理，也不会让没有命令能力的子代理去跑构建或验证命令；
- **删除**：列表里左滑条目，会删掉对应的 `.md` 定义文件，不可恢复。

### 批量操作

列表右上角的「多选」按钮（方框带勾的图标）可以一次处理多个子代理：

1. 点「多选」进入多选模式，每行左侧出现勾选框，整行点击即勾选；「当前项目 / 全局」两个分组共用一份选中集合。
2. 顶部操作条提供「启用 / 停用 / 删除」与「全选 / 取消全选」，最右「×」或系统返回键退出多选。
3. 「全选」包含折叠起来的那个分组。
4. 删除会弹确认框；确认后逐条删除定义文件，期间显示「正在删除…」，完成后列表刷新并退出多选。远程模式下删除走 SSH，条目多时请等提示消失再离开页面。

多选模式下不能点击进入详情页，也不能左滑删除单条。

新建和编辑时，表单会避让软键盘；提示词正文较长时可以上下滚动，继续编辑末尾内容。

启停状态存在 `agents.json`，与技能的停用名单同一套约定：全局名单位于当前执行环境的 `~/.aicode/agents.json`，本地模式保存在手机 App 私有目录，远程模式保存在服务器上；两者独立，不会自动迁移或同步。项目级名单在本地模式位于 `<工作区>/.aicode/agents.json`，远程模式仍保存在手机 App 私有目录，按服务器和工作区隔离。两级取并集，任一作用域禁用即生效。

在 App 中切换启停状态后列表会刷新。本地模式下手工修改定义或名单，列表几秒内自动刷新；远程模式下不会监听服务器上的文件变化，手工修改后需退出并重新进入设置页刷新列表。

## 运行机制与限制

- **并发上限**：系统最多支持 **5 个子代理同时运行**，超出时需等待已有任务完成或手动暂停；这不限制协作分组中可查看的实际子代理数量；
- **防嵌套**：子代理不能再派生下一级子代理；
- **双向通讯**：主会话可随时向运行中或已完成的子代理追加消息（可重复发送），子代理运行中也能主动向主会话汇报或求助；消息异步送达、互不阻塞。
- **授权管控**：子代理的普通工具调用与主会话一样自动放行；项目/全局禁止规则优先，Shizuku、`sudo`/`su` 和高危操作使用同一套安全策略。高危工具审批可选择「拒绝」「仅本次允许」「本会话始终允许」，详见 [工具授权](/guide/permissions)。每个子代理会话的高危工具授权独立保存，不继承父会话或其他子会话的授权；同一子会话重启后仍保留。计划审批不保存这种授权。需要限制某个子代理能调用哪些工具时，用 `tools` 和 `disallowedTools` 配置白名单与黑名单；

- **你手动停止也会告知主会话**：在子会话里点停止、或直接删掉一个正在运行的子代理时，主会话会收到一条「已被手动终止」的通知（而不是执行失败），AI 不会自行重新派发；并发名额也会立即释放；
- **生命周期**：删除子会话保留主会话已保存的交互记录并显示已删除；删除父会话时，其包含的所有子代理会话及所属交互记录一并清理；
- **定义改动的生效时机**：新增、改名或修改子代理定义后，已打开的会话仍沿用开场时的清单，**新开一个会话**才能让 AI 看到改动。
