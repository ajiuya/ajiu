# 备份与还原

「设置 → 备份与还原」可以把应用配置、聊天历史、凭据、工作区文件，以及按需选择的记忆、技能、提示词和插件导出为备份文件，也能从备份还原回来。本地导出可选择是否加密，上传网络备份必须设置加密口令。

## 导出

页面上方保留原有七项：**AI 供应商、连接与同步、聊天历史、MCP 服务器、授权规则、应用设置、工作区文件**，并追加以下四项。**记忆、技能、提示词、插件首次均默认关闭**，各项独立选择；勾选状态会记住，下次进来沿用。

| 追加范围 | 包含什么 |
| --- | --- |
| [记忆](./memory.md) | 手机侧全局记忆、已登记本地项目记忆，以及手机保存的 SSH 项目记忆；Markdown 文件按原样保存，保留原文件名、文件头中的名称与摘要及正文。 |
| [技能](./skills.md) | 手机侧全局、已登记本地项目的完整技能目录，以及**当前已连接 SSH** 的全局与当前项目技能；包括定义、配套脚本、资源、参考资料及相应的启停配置。 |
| [提示词](./custom-prompts.md) | 手机侧全局、已登记本地项目和手机保存的远程项目自定义内容；包括 `prompts.custom/` 中的片段、`agent/` 覆盖、`.no-builtin` 开关与 `prompts.json` 启停配置，不打包可由 App 重建的内置提示词副本。 |
| [插件](./plugins.md) | 已安装插件的安装内容、保存在插件私有数据中的配置与文件，以及可迁移的插件密钥；不要求为备份临时启用插件。 |

需要备份 SSH 技能时，先连接目标服务器并选中远程工作区；这里只采集当前连接的全局与当前项目，不遍历所有已保存服务器。项目技能的启停配置仍随手机保存的对应远程项目配置备份。技能目录不会因名称与内置技能相同就被排除，你编辑过的内置技能也会保留；已安装依赖、虚拟环境、Git 目录及缓存不随技能打包。项目进展、交接和归档历史仍由「聊天历史」控制，不属于这里的 Markdown「记忆」。

「插件」按已安装文件重新打包，保留安装内容，不保证与最初下载的 ZIP 文件逐字节相同。通常在插件配置页保存到私有数据的设置会一并保存；宿主管理的依赖及备份导入、导出缓存不包含在内。**插件提供商账户与 API Key 仍由原有「AI 供应商」选项控制**，不因勾选「插件」就一起导出；浮层位置和插件市场全局偏好也不在本项范围内。

四项勾选只决定备份内容，**不会授予 Root、Shizuku 或插件权限，也不会执行记忆、提示词、技能脚本或插件动作**。

**工作区文件默认关闭**，需要时手动打开。它会打包所有本地模式的内部工作区文件，包含 `.git` 目录，因此仓库历史和未推送的提交都能完整还原。通过「添加外部工作区」加进来的外部工作区属于你设备上的原始目录，不会被打包。排除规则是各工作区自己的 `.gitignore` 加上同步功能的默认忽略清单（`node_modules`、`build`、`dist` 等），符号链接不备份。

::: tip 代码优先用 Git 备份
Git 仓库本身就完整保存了代码和历史，这里的导出更适合作为额外的备用手段，而不是主要的代码备份方式。
:::

点「导出备份」后会弹窗设置口令：

- **填写口令**：使用 AES-GCM 加密。
- **留空**：输出明文 tar.gz。

通过系统文件选择器将备份保存到你指定的位置。按所选范围，备份可能包含 API Key、SSH 凭据、自定义文件中的敏感信息及插件密钥。插件密钥在导出时受控解密后写入备份，留空口令时这些内容可直接被读取；还原后会用目标设备的系统密钥库重新加密保存。建议设置口令，分享前先检查内容。

::: danger 务必牢记加密口令
加密备份在遗失口令时无法解密恢复，没有任何后门或找回途径。
:::

## 插件扩展区段

原有「插件扩展数据」与上方「插件」完整备份是两种独立选择。扩展方式由已启用、声明备份用途且获得备份能力授权的插件参与，可执行其声明的备份或还原处理；默认不选择，勾选也不替插件授予能力。扩展数据随插件 ID 分区打包，不自动包含其他插件的私有内容。

还原预览可再次选择扩展区段，未选择、插件不可用、权限不足、失败与成功分别报告。扩展还原不会安装或启用插件；如果同时选择某个插件的完整还原，该插件的扩展还原会被取消选择并跳过，不同时运行两种还原。不会为了备份临时启用插件，也不把历史审批或备份内容当作执行许可。详见[插件](./plugins.md#备份扩展)。

## 导入

导入前请**先另存一份当前数据的备份，并停止正在运行的任务和插件动作**。原有配置与聊天历史沿用合并方式，不清空整个应用；工作区文件及明确选择覆盖的内容仍可能被替换，不能把“合并”理解为绝不覆盖。加密备份需要输入对应口令，未加密的备份留空即可。

只有导出时勾选了「应用设置」的备份才会恢复主题、配色和偏好设置，包括备份中已有的聊天字号比例、聊天背景透明度、打字机速度与思考自动展开。单独导出的聊天记录，以及未勾选「应用设置」的备份，导入后会保留当前应用设置。

备份会先保存为本次导入使用的临时副本；加密文件在预览前完整解密并校验，确认恢复时复用副本，不再重复解密。新增四类内容的文件完整性、路径、数量和大小限制会在写入原有配置与聊天等数据前先行校验，校验未通过时不进入写入。较大的备份需要足够的应用内部存储空间保存临时文件；完成、取消或失败后会清理这些临时文件。

备份含工作区文件、上述四类内容或插件扩展数据时，会弹出「选择还原内容」：

1. **核对范围**：按记忆、技能、提示词、插件分类，查看手机全局、手机项目、手机保存的远程项目配置或 SSH 位置，并核对来源、工作区、插件及文件数和大小。新内容默认都不选；全部不选也能继续还原备份中原有的配置与聊天历史。工作区文件和插件扩展数据分别选择。
2. **决定是否覆盖**：「覆盖所选分区中的同名内容」默认关闭。记忆、技能和提示词遇到同名文件时保留当前文件并报告冲突；明确打开后才替换所选范围中的同名文件，不删除其他现有文件。不要为跳过冲突提示而直接打开覆盖。
3. **核对完整插件**：本机已有相同插件 ID 时，默认整项报告冲突，不只恢复其中的数据。明确打开覆盖后才一起恢复备份中的安装内容、私有数据及密钥；其他插件不受影响。请先确认备份版本和数据确实是需要保留的一份。
4. **确认 SSH 目标**：SSH 内容默认不选。需要还原时，先连接并选中目标远程工作区，核对「当前 SSH 还原目标」显示的账号、服务器和项目，再打开目标确认开关。没有可用连接时，SSH 内容不可选，但仍能还原手机侧内容。切换执行环境、服务器、工作区或目标根目录后，相关远程写入会停止并报告不可用或部分还原，须重新预览确认；不会改存到手机。
5. **确认恢复并查看报告**：逐项核对成功、未选择、冲突、不可用、部分还原或失败，以及已还原、跳过和冲突数量。主数据成功不代表新内容或插件扩展全部成功。

手机保存的远程项目配置仍按原来源隔离；新设备上可以新建对应的手机配置目录，不会自动绑定到任意同名服务器或工作区。还原目标由当前应用中可用的配置位置确定，不按备份里记录的旧绝对路径任意写入设备或服务器。

::: warning 恢复工作区会直接覆盖
勾选的工作区会覆盖本地同名工作区里的文件，且无法撤销。本地没有同名工作区时会自动新建一个再写入，因此更换设备或重装后不会丢数据。远程模式的工作区（文件在服务器上）不参与还原。
:::

导入完成后会显示还原数据的汇总清单：供应商、远程连接、远程挂载、聊天会话、聊天消息、待办项、MCP 服务器、全局授权规则、工作区文件的恢复数量，以及记忆、技能、提示词、插件和插件扩展的逐项结果。

完整还原的插件会作为一次新安装，保持停用；**不恢复信任确认、能力与操作授权、真实系统 Root／Shizuku 授权、内部执行许可、来源捕获、其他适用的会话授权、自启动许可、运行中状态及已安装依赖**。完整备份与还原本身不运行插件的安装或清理脚本。确认内容可信后，再到插件页重新启用并按需授权；依赖需按正常流程另行准备。

::: warning 部分还原不等于全部回滚
新增文件、插件安装内容、私有数据与密钥，以及原有聊天数据和项目历史，并非整个备份的一次性事务。插件可能已恢复安装内容，但数据或密钥未全部成功。出现「部分还原」时，请先看报告并核对已经成功写入的部分，再决定如何补救；不要假定失败后所有数据都保持导入前的状态，也不要盲目重复覆盖。
:::

旧版本备份中的 Agent 工作模式信息会被忽略，不会恢复旧的模式选择；聊天内容和其他可恢复配置仍按所选范围导入。旧项目/全局允许规则即使被恢复，也不再参与工具授权裁决，详见 [工具授权](/guide/permissions)。

聊天会话会按备份时的所属工作区归位：本地有同名工作区直接还原过去，没有同名工作区时会自动新建一个空工作区再挂入会话（与「恢复工作区」自动新建的逻辑一致），更换设备或重装后各工作区的会话不会集中到同一处。

## 应用设置与外观

导出时勾选「应用设置」，会一并保存[外观主题](/guide/appearance)中的**聊天字号比例**、**聊天背景透明度**与[偏好设置](/guide/general#打字机速度)中的**打字机速度**，以及**思考自动展开**。导入时，只有备份实际含有且非空的新设置才会写回；旧备份缺少其中某项或值为空时，不会用默认值覆盖本机当前值。打字机速度以字符/秒保存，不是 token/秒；导入的值低于 30 时按 30 恢复，高于 350 时按 350 恢复。

全局背景与聊天背景的**图片本体和本机绝对路径均不备份**，导入也不会用旧路径替换当前图片。更换设备或重装后需要重新选图；只恢复聊天背景透明度，不会自动带回背景图片。

「软件权限」中的 **Root 总开关和本机授权身份不随 App 备份迁移**，本机现有开关不由备份改写。其他设备恢复后仍须自行满足设备 root、系统 su 管理器真实授权及总开关条件；默认放行不代表备份能授予系统 Root，也不会把系统 su 拒绝显示为可用。Shizuku 的系统授权、真实服务身份与活跃连接同样不能由备份恢复，ADB shell 身份不能当作 Root；请在 Shizuku 中启动服务并授权本 App，再核验当前连接。

CHROOT 新操作由内部重新自动绑定 owner／source，避免切换工作区后错写，无需用户来源授权，不能从备份继承旧的内容摘要、实例或 Root 代际捕获。CHROOT 正常容器操作默认放行，仅可识别的 Android 宿主系统／共享内核路径修改，或有具体宿主路径线索但行为不明确时先审批；未知程序、动态路径或交互输入本身不自动触发审批。Root／Shizuku 直接操作宿主，可确认只读默认放行，修改或无法确认是否只读时先审批。触发审批时可仅本次或本聊天会话允许同一工具、同一来源及身份的全部后续宿主修改与不确定操作，包括不同命令和目标，不限当前命令。**新的宽范围 session grant 仅存内存，进程重启清除，不随备份导出或还原**；来源、身份、Root 代际、Profile 配置内容或选择、实例改变后需重审。单次批准、逐命令完整命令绑定的内部 permit、待决审批及独立计划批准均不恢复，旧版 Root／Shizuku 会话记录也不转成新的宽授权。PRoot／SSH 的旧 `sudo`／高危提权 grant 仍按原有完整精确命令和有效范围规则处理，不因新宿主策略而扩大。本机保护项不被旧备份覆盖，导入不自动建立通道、重跑命令或恢复旧现场；显式禁止、真实系统权限、当前 CHROOT 来源、实例身份和清理核验、独立计划及实例创建／停止／移除确认不变；历史任务 UNKNOWN 保留诊断但不单独阻止新任务，异常实例核验通过后可在当前开机期间直接重试删除，无需重启，详见[工具授权](/guide/permissions)。

## 聊天历史中的上下文快照

导出范围中包含「聊天历史」时，消息已有的上下文输入量、当时的有效输入预算、是否估算，以及**系统提示词、工具定义、聊天历史、工具结果、图片的本地估算分项**会一并保存。导入后仍按各条回复的快照显示[上下文占用及详情](/guide/chat#上下文占用)，不按当前模型重算；分项之和不保证等于供应商报告的精确输入用量。

旧备份或旧消息没有占用快照时，仍可恢复聊天内容，但对应的上下文占用显示 `—%`，不会补算为 0% 或套用当前会话的比例。已有总量但没有分项时，详情显示「未记录」，不反推旧数据。手动压缩只改变当前会话上下文，不改写这些历史快照。

快照与分项随聊天历史保存，不要求额外勾选「应用设置」；聊天字号、聊天背景透明度和打字机速度则属于应用设置，不属于消息快照。

## 项目历史与恢复状态

导出时勾选「聊天历史」，会保留消息当时实际使用的模型输入快照，并导出独立的项目进展、交接和归档历史。原消息正文不被项目历史替换；旧备份没有这些字段时仍能恢复普通聊天。

聊天历史会保留已经关联的续接记录，以及当时展示的「不完整、未验证」草稿，方便回看。运行中的恢复账本、待恢复请求、待投递通知、尚未提交的正文草稿、项目绑定和进程检查点不作为可执行任务导入。导入已有会话会使旧执行代际失效，过期回调不能重新写回；历史中的“执行中”工具按中断处理，不自动重跑工具、模型请求或子代理，也不恢复审批决定。

同一项目记录的内容有冲突时，会保留当前用户版本并报告冲突，不暗中覆盖；Room 聊天数据与独立项目历史分别提交，不保证整个备份跨两种存储一次性回滚。导入前仍应停止正在运行的任务：阻止迟到写入并不能撤销已经发生的外部副作用。

## 子代理交互记录

导出时包含「聊天历史」，会一并保存主会话所属的**子代理交互记录**，包括已记录的派发、双方消息、你从卡片发送的补充指令及其排队取消记录，以及完成、失败、停止、中断和删除信息；已有的真实完成正文、已记录的代理名称也随记录保留。不需要另勾「应用设置」。

恢复后，这些记录用于回看[子代理协作卡片](/guide/subagent#主会话中的协作卡片)中的往来，**不是待执行任务清单**：还原会话和记录不等于恢复执行，导入不会根据这些记录自动新建任务、启动或重新派发子代理，不重发补充指令，不重跑工具，也不把历史审批当作有效许可。之后的新请求与审批仍按正常流程处理。

- **旧备份**：没有独立交互记录时仍可恢复聊天，只从已有内容提供历史回看；不会补造缺失的消息、完成结果或执行状态，也不会根据旧指令自动继续任务。
- **排队但未开始的补充指令**：保存有这次发送记录不代表已执行。即使曾调整队列顺序，尚未真正开始的请求在重启后仍显示为中断，不自动重放；若要继续导入记录里的任务，请主动重新发送。本机仍有待续接请求时，可用输入框右上角的「继续｜放弃」气泡处理。
- **已取消的排队指令**：从队列删除或停止全部任务时留下的取消记录随历史保留；恢复后不会重新进入队列，也不会被算成一次已执行的请求。不因此抹掉后续新请求的真实完成记录。
- **子会话已删除**：主会话保留的交互记录仍可随聊天历史备份、还原，并显示已删除，不会因此复活子会话或恢复发送、停止等操作。删除主会话会清理其所属记录，但不会修改你此前导出的备份文件。

交互记录可能包含任务要求、文件路径与公开回复，分享或上传备份前请检查内容并按需加密。它保存的是实际往来，不把子代理私有思考加入主会话卡片；备份恢复本身也不是继续执行或授权的用户指令。

## 网络备份

除了导出成本地文件，还可以把备份直接上传到云端，或从云端拉回还原。备份页底部有「本地备份 / 网络备份」两个标签：本地页管导出范围与导出/导入，网络页管备份目标。切到「网络备份」后用右上角「＋」添加**备份目标**，支持两类：

- **WebDAV**：填服务器地址（含路径，如 `https://dav.jianguoyun.com/dav`）、远端目录、用户名和密码。
- **对象存储 (S3)**：填服务地址、区域、存储桶、Access Key / Secret Key，可加 Session Token 与对象前缀，路径风格寻址可切换。兼容 AWS S3、Cloudflare R2、阿里云 OSS、腾讯云 COS、MinIO 等 S3 兼容服务。

每个目标都能「测试连接」验证配置。配置好后：

- **上传到云端**：导出当前勾选的备份并上传到所选目标；**必须填写非空口令，使用 AES-GCM 加密，不能留空上传明文**。需要调整记忆、技能、提示词或插件等范围时，先在「本地备份」页修改勾选，再上传。
- **从云端恢复**：列出所选目标上的备份（按时间倒序），选一个下载并还原，流程与从本地文件导入一致，包含口令校验、内容选择、覆盖决定和必要的 SSH 目标确认。

每个目标卡片底部都有「上传」「恢复」按钮；点卡片进入编辑，左滑删除。

远端文件名形如 `aicode-backup-<时间戳>.tar.gz`。备份目标里的密码与密钥由系统密钥库（Android Keystore）加密保存，与备份本身的加密口令相互独立。

::: warning 妥善保管云端备份与口令
网络备份强制加密，但仍可能包含 API Key、SSH 凭据与插件密钥。请限制备份目标的访问权限，妥善保存口令；不要将本地导出的明文备份另行上传到公共存储。
:::

## 补充说明

备份口令只作用于导出的备份文件本身。应用内部存储的 API Key、连接密码、SSH 私钥等敏感配置另由系统密钥库（Android Keystore）加密保存，与备份口令相互独立；更换设备时请通过备份导入迁移，直接拷贝应用数据目录会因密钥不匹配而无法解密。
