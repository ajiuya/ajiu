# 会话目标（Goal）

「目标」让 AI 围绕一个你给定的结果**自主循环**推进：它自己规划、执行、验证，并在每轮结束时判断目标是否达成，直到完成、暂停、受阻或达到预算上限才停下来；需要计划审批时也会等待你的决定。适合那种「有一个明确终点、能自己验证进度」的任务，例如「让 checkout 测试全绿」「把某个接口的 p95 延迟降到 120ms 以下」。

::: tip 版本说明
目标功能自 1.13.0 起引入。
:::

## 设定目标

在输入框输入：

```
/goal 让当前分支的单元测试全部通过，且不改动公开 API
```

AI 会立即开始自主循环。目标会让 AI 自动续跑，不代表对超出当前任务范围的操作授权。普通工具调用按统一规则自动执行，项目/全局显式禁止规则优先，具体见 [工具授权与安全策略](/guide/permissions)。

Root、Shizuku 与本地 CHROOT 中，可确认只读的宿主系统文件操作默认放行；修改宿主或未知脚本、动态路径、交互行为等无法确认是否只读时先审批，实际只读脚本也可能弹窗。可仅本次允许（`ONCE`），或本会话始终允许（`ALWAYS_SESSION`）：后者覆盖本聊天 session、同一 tool、同一 source／identity 的全部后续宿主修改与不确定操作，包含不同命令和目标，不限当前命令，不跨工具、来源、身份或父子／其他会话。新宽授权仅存内存，进程重启清除；来源、身份、Root 代际、Profile 配置内容或选择、实例变化后需重审。有限静态识别不是运行时拦截或沙箱。CHROOT 普通来源仍按策略绑定，无需逐来源设置确认，但不能借用其他会话的捕获。目标续跑不能绕过显式拒绝、Root 总开关、真实 OS 授权、Shizuku 身份或每条完整命令绑定的内部 one-use permit；宽授权不是无限 OS Root 权限。身份、实例或通道状态 UNKNOWN 仍拒绝执行，旧捕获撤权后不能继续使用。

PRoot／SSH 的 `sudo`／`su` 与适用高危命令保留原有会话授权、完整命令匹配及 `elevate` 规则，不与上述默认放行混用。独立计划审批、插件内容启用与宿主能力、依赖准备和实例创建／停止／移除确认仍分别处理，目标续跑不能代替。

一个好的目标要能自证：

- 说清「什么算完成」和「怎么验证」，例如「跑 `./gradlew test` 全绿」「页面能本地构建成功」。
- 指向 AI 该读的文件、日志或参考。
- 弱目标「写一下这个功能的文档」；强目标「产出 Goals 的文档页，说明生命周期与命令，并确保本地构建通过」。

## 查看与管理

| 命令 | 作用 |
| --- | --- |
| `/goal <目标>` | 设定或覆盖目标，并立即开始 |
| `/goal` | 查看当前目标与状态 |
| `/goal pause` | 暂停自主循环 |
| `/goal resume` | 恢复自主循环 |
| `/goal clear` | 清除目标 |

输入框下方会常驻显示目标提示条，标注状态（进行中 / 已暂停 / 已完成 / 受阻 / 预算耗尽），并提供暂停、恢复与清除按钮，不必记命令。

## 运行中会发生什么

- 每轮正常结束后，AI 会对照目标与证据判断是否达成；未达成、预算未耗尽且没有等待审批或暂停时，就自动进入下一轮，不会反复问你「是否继续」。
- 想中途插手：直接发消息即可。你的消息优先于续跑执行，处理完再继续目标。
- 达成时 AI 会把目标标记为「已完成」；遇到需要你介入的阻塞（缺凭证、需决策）会标记为「受阻」并停下。
- 点「停止」打断时，目标会自动暂停（避免下条消息后继续自动跑），用 `/goal resume` 恢复。
- 安全阀：自动循环连续 3 轮没有任何进展（无工具调用也无可见输出）时，会自动置为「受阻」并停止，避免空转消耗 token。
- 达到预算上限会自动停止并标记为「预算耗尽」，此时可 `/goal resume` 继续或 `/goal clear` 清除。

## 目标中的计划审批

持续目标不代表可以省略规划确认。复杂、高风险、影响面不明或你明确要求先规划时，AI 会先只读检查并提交完整方案；普通小改不强制审批，已明确批准且范围未变的方案也不必重复提交。

- **等待审阅**：聊天中显示计划摘要卡、所属会话和等待状态，点「查看计划」阅读完整内容。等待你审阅属于正常等待，不是目标已完成，也不应靠自动重试跳过。后台通知只提示回 App，不提供直接批准计划的按钮。
- **批准执行**：只批准当前方案，不设「始终允许」。与计划提交混在同一批的其他工具调用都标为未执行，AI 必须获批后重新发起，不会自动补跑。
- **拒绝并结束**：可先填拒绝意见。本轮结束，**该会话的目标立即暂停**，不会再自动请求 AI 回答、修改后重提、补送后台提醒或消费排队消息继续跑。没有取得有效批准时同样停止，不会再等待三轮才暂停。

要继续修改方案，请主动发送下一条消息，例如「按刚才意见调整计划，重新提交审批」。拒绝意见本身不会自动触发改稿；`/goal resume` 也不等于批准被拒绝的计划，仍需重新提交并由你审阅。

各会话和子会话的计划审批独立，待审批请求只存在于内存，取消时清理、重启后需重提。计划审批没有「始终允许」，不会转成宿主会话授权；宿主修改／不确定操作的 `ONCE` 或 `ALWAYS_SESSION` 需另行决定，新的宽授权只存内存且进程重启清除。PRoot／SSH 按原有完整精确命令规则保存的授权仍须核验有效范围。批准计划不会覆盖显式禁止、真实系统授权与身份检查，不替代宿主修改／不确定操作审批、PRoot／SSH 高危提权或其他独立确认，也不扩大原目标范围。目标和任务待办功能都保留，审批与进度跟踪相互独立，详见[计划审批](/guide/permissions#计划审批)。

## 预算上限

自主循环会持续消耗 token，因此有两道保险，可在 **设置 → 偏好设置 → 目标（goal）** 中调整：

- **最大续跑轮数**：默认 50 轮。
- **token 预算**：默认 50 万，按循环期间的输入+输出 token 累计。

任一触顶即停止循环并提示。

## 注意

- 目标按会话保存，切换会话互不影响。
