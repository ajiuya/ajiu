# 容器与镜像

AiCode 中 AI 执行命令的环境称为「容器」，入口在「设置 → 容器与镜像」。列表为单选，选中的容器即 AI 命令执行、文件读写与终端所在的环境。

后端分为**本地容器**与**远程 SSH**（见[远程 SSH 模式](/guide/remote-ssh)）。本地默认使用 PRoot；已有 Root 的 ARM64 设备可新建独立 CHROOT 实例。运行时创建后不能就地转换。健康 CHROOT 实例的实际来源默认允许，无须分别确认聊天、终端或文件页授权；总开关与系统实际权限仍须有效。

聊天提示中的“运行环境”按当前所选配置区分 PRoot、CHROOT 与远程 SSH；未创建实例或配置未就绪会如实注明。这是配置说明，不是一次实际启动或健康检查。`id` 显示 `uid 0`、Ubuntu 等发行版名称以及 Android 内核版本都不足以单独判定 PRoot 或 CHROOT，核对实际命令环境时还需结合该次执行来源；不要把 CHROOT 当作安全沙箱。

## CHROOT 实例

CHROOT 使用独立镜像目录和 home，不接管已有 PRoot 镜像。设备须已有 Root，并在「设置 → 软件权限」开启 Root；App 不为设备取得 Root。容器内以 root 运行，镜像系统目录可写，可以使用发行版包管理器。控制通道及手机来源目录仍验证 App 身份，不把宿主根目录整个挂进容器，也不提供共享 systemd/init。

1. 添加本地镜像时选择 **CHROOT**，选好本地归档、已下载镜像或内置最小镜像，阅读写盘和 Root 前提提示后点击 **添加并创建实例**。此按钮同时同意保存新配置并从当前镜像创建独立的可写 rootfs 与 home，无须再返回实例卡点一次创建；不会自动选中或激活。镜像必须包含可执行的匹配架构 shell；预装工具是否齐备取决于镜像，最小镜像不等于开发环境已经就绪。
2. 明确选中该实例，从实际入口使用聊天、终端、文件页、Git或本地 MCP；普通操作默认允许，不再先失败一次再到设置页逐项授权。
3. 每个真实来源由内部自动建立独立运行绑定，使用时核对实例、配置、工作区和 Root 代际，避免切换后错写；这不是用户来源授权。需要时建立真实 Root 通道，系统 su 管理器仍可能要求你授予本 App 权限。
4. 来源、配置、Root身份或连接变化后，旧绑定和执行票失效；新操作重新捕获真实来源，不复活旧任务。缺Root或清理未知时如实失败，不擅自切到PRoot。
5. 停止实例会阻止新任务并等待已有任务清理。**正常删除不需要重启手机**，完整清理确认后即可删除。界面显示“存在活动任务或清理待确认”时，不能据此认定任务仍在运行或已经清理。只有无法验证旧任务已退出的异常实例，才使用下述登记后重启的恢复流程。

聊天中的图片、文件和拍照附件自动使用当前会话所选容器与工作区，CHROOT 无需额外来源授权。选择附件后切换会话、工作区或容器，会取消旧上传，旧结果不会写入新目标。

启动过程中取消文件或命令请求时，尚未派发的请求会撤销；已经派发的请求会保持控制连接，在身份认证及准备完成后停止，不再放行用户命令。清理仍须在限定停止期限内获得完整确认，不能仅因取消就认定清理成功。此行为不会自动解除此前留下的 UNKNOWN。

已经启动并迅速结束的命令会按实际退出状态返回结果：退出码为 0 表示命令正常结束，非零退出码保留为命令结果，不会仅因结束得快而报“启动失败”。返回可信退出状态仍需要完成清理核验。

添加／下载导入期间，两页都显示保存及创建进度与结果。Root 总开关关闭、系统 Root 不可用、配置或 Root 代际变化、实例操作忙碌或清理未知时不会继续创建，也不会自动启用 Root、重新授权或切换运行时。只有配置确已保存后，失败提示才会说明配置被保留；可在实例卡核对状态后手动点击原有的「创建 CHROOT 实例」重试，该独立创建及停止／移除操作仍保留确认。下载记录的「已导入」只代表配置保存，不代表实例创建成功。取消不会发起迟到的创建或自动重试；若 Root 操作已经开始，请以实际实例状态及清理核验结果为准。

编辑已有配置、重进设置、界面重组或恢复旧配置都不会自动创建，不自动迁移或清理旧实例。

若显示 **UNKNOWN／清理结果未知**，新的启动和重装仍会被阻止。打开「容器与镜像」，点击行尾铅笔可使用以下操作：

- **修复运行记录**：仅在主记录完整、临时写入中断时可用。先保留原记录，再恢复可读状态；未完成任务仍记为 UNKNOWN，不会改成成功，也不会重放任务。主记录损坏时不能用此入口强行清空。
- **异常实例删除**：会删除该容器系统内的文件和已安装软件。运行记录可修复时会先修复，再核验并登记删除请求。首次登记后实例尚未删除，需要**重启手机**，返回同一入口再次确认删除；仅重启 App 不够。可以先为多个待删实例分别登记，再统一重启一次。

列表左滑删除异常实例，也会进入同一确认流程。删除成功才移除配置；下载的共享镜像文件、项目目录及 App 管理的 home 不在此删除范围内。没有创建实例且没有未处理安装记录的配置，可直接删除配置。

如果身份发生变化、记录损坏、目录仍有异常挂载或删除过程再次中断，会保留失败状态和证据，不把目录缺失当成成功。重试任务或重启 App 不会清除 UNKNOWN；若继续使用其他健康容器，需要明确选择，切换不代表原任务已经完成。不要手动删除目录、修改记录或把“找不到进程”当作清理成功。

发生运行故障时，App 在私有、不参与备份的目录保留最多 64 个故障任务的有界诊断。启动失败和后续阻断提示会附上已有的任务编号、首次失败分类／阶段、校验过的原生错误码及清理结果。停止超时还会保留触发来源和截止时尚缺的完成确认，例如辅助进程退出或输出管道结束；这是当时的冻结记录，后续状态变化不会改写它。旧版记录没有这些字段时不补造。诊断不记录命令、环境变量、控制令牌或原始 stderr。诊断写入失败不会放行实例，也不会把 UNKNOWN 改成成功；记录仅用于定位原因，不是清理证明。旧版未保存的错误不能由新版本补回，进程在异步写入完成前退出也可能缺失最近证据。

**旧版只读实例不会自动升级**：新的可写 Root 实例需要支持镜像内文件变化的清理格式。旧只读格式会明确拒绝直接以可写 Root 启动，请保留旧实例并新建 CHROOT；不会改写旧清单、自动迁移内容或自动删除。旧实例的标准移除仍需原有身份及完整清理证明；异常删除同样需要身份核验和上述重启流程。

CHROOT 不运行下文的 PRoot 初始化菜单，但可按镜像与实际系统条件使用自带包管理器，例如 Ubuntu／Debian 的 `apt update`、`apt install`。在 Git 页面主动克隆或初始化仓库时，若缺少 Git，会先准备所需依赖；后台仓库检查不会触发安装，详见 [Git 管理](./git.md)。最小镜像不等于开发工具已就绪，安装会联网、占用存储且可能运行软件包维护脚本；AI 安装仍应符合你的任务范围。`apt`、`npm`、Python 脚本及相对路径写入等正常容器操作默认放行，不因软件包维护脚本或程序行为未知而自动审批；guest 自己的系统目录写入不是宿主修改。systemd/init 和必须直接操作 Android 内核的服务不因此获得支持。归档仍有展开大小、单文件与条目数限制，正常 setuid/setgid 权限位可以保留，路径穿越及不支持的特殊设备仍被拒绝。

设备真实 Root／capabilities、Ubuntu／Debian `apt` 流程及旧 OART 故障仍待实机验收；本页的策略与使用说明不代表这些路径已验证通过。

镜像内 `/etc`、`/usr`、`/var` 可写，不把它们误当宿主系统文件。App提供的只读配置、DNS及其它只读挂载仍只读。文件桥覆写保留原有mode/owner，部分不支持的链接树或跨文件系统重命名仍明确失败。任意Root命令可能更改共享工作区属主或权限，不会为此事后递归chown全部项目。

### 宿主只读、修改与不确定操作

CHROOT 正常容器操作，包括终端 `send`／`key`，默认 `ALLOW`；单纯未知程序、动态路径或交互输入不自动要求审批。仅可识别的 Android 宿主系统／共享内核路径写入，或有具体宿主路径线索但行为不明确时先审批；可确认只读和 `/dev/null` 等无害输出默认放行。

Root／Shizuku 直接作用于宿主 Android：能确认只读时默认 `ALLOW`，修改宿主或无法确认是否只读时先审批。触发审批时可选「仅本次允许」（`ONCE`）或「本会话始终允许」（`ALWAYS_SESSION`）。后者覆盖本聊天 session、同一 tool、同一 source／identity 的全部后续宿主修改与不确定操作，包含不同命令和目标，不限当前命令，也不跨工具、来源、身份或其他／父子会话。

新的宽授权仅存内存，进程重启清除；来源、身份、Root 代际、Profile 配置内容或选择、实例改变后需重审。每次 Root／Shizuku 执行仍消费完整命令绑定的 one-use 内部 permit，不能重放。显式 `DENY`、Root 总开关、真实 OS 授权、CHROOT UNKNOWN／清理约束和独立 CREATE／STOP／REMOVE 不变；计划、插件信任及依赖准备仍独立。PRoot／SSH 原有 `sudo`／`su`、高危提权和精确命令会话授权不改，详见[工具授权](/guide/permissions)。

::: warning 不是 Root 安全沙箱
CHROOT 与宿主共享内核，不提供 PID/user namespace、信号或 ptrace 完整隔离，也不能保证特权程序结束全部监督进程后仍可回收。宿主判断只是有限静态识别，不执行或打开脚本、不推导拼接路径，也不能全面拦截宿主访问；符号链接、`PATH` 解析及任意程序的实际副作用仍不能保证。容器 root 是真实权限上下文，不是安全沙箱。不要运行不可信代码，宽授权也不是无限 OS Root 权限或任务范围扩张。
:::

## 容器列表

每行是一个容器配置，名称后附来源标记：内置、自定义、SSH。当前生效的那个容器，名称显示为主题色。

列表排序和编辑入口适用于各类配置；以下重置与镜像清理说明主要针对 PRoot，CHROOT 使用上面的实例管理流程：

- **排序**：长按行的名称区域上下拖动可调整顺序（重启后保持）；新添加的容器排在列表最前。
- **编辑**：行尾铅笔图标。
- **重置**：编辑弹窗右上角刷新图标。此为破坏性操作，会删除容器内已安装的工具与配置，需二次确认；确认后正在运行的 AI 会话与所有终端标签都会关闭。内容较多的大型容器删除可能耗时数十秒，期间显示「正在清理容器数据」及已清理项数，完成后自动关闭，界面不阻塞。
- **删除**：行上左滑露出红色删除按钮。删除本地镜像会一并清理其 rootfs 释放空间（同样显示清理进度）；删除远程 SSH 仅删除配置，不影响服务器数据。

内置 Alpine 也可删除。全部删除后列表显示空态，可一键恢复内置 Alpine，无需担心误删。

容器运行后，App 会自动识别其系统类型，在列表左侧显示对应图标（支持 Alpine、Ubuntu、Debian、CentOS），无法识别则显示默认图标。

## 内置 Alpine 容器

App 自带 Alpine 镜像，首次启动时自动加入列表并选中，shell 路径已自动配置，无需额外设置。

::: tip 首次使用需进入终端完成初始化
本地容器的环境准备（解压 rootfs 及安装基础工具）在首次进入**终端页面**时触发。首次使用请先进入终端完成初始化，之后 AI 命令执行、Git 管理与本地 MCP 才能正常使用。
:::

::: info 内置容器的版本不会随 App 升级被替换
新版本 App 可能内置了更新的 Alpine 镜像，但**升级 App 不会动你已经在用的容器**——你在里面装的工具、软件源配置都会原样保留。

想换到新版基线，请在「容器与镜像」里对该容器点**重置**：重置会删除它的 rootfs 目录（含容器内已安装的工具与配置），下次进终端重新解压并初始化。**工作区文件与 AI 配置（skill、MCP）不会受影响**——它们存放在容器之外。新装的 App 首次初始化则直接使用内置的最新镜像。
:::

## 首次进终端的初始化菜单

使用 PRoot 时，无论内置 Alpine 还是自行导入的镜像，rootfs 解压完成后首次进入终端都会弹出初始化菜单，含四个选项：

**1. 自动安装依赖（推荐）**

列出待装项（bash、curl、ripgrep、git 等基础工具，以及 Node.js 和 Python 3），输入 `y` 确认后选择软件源并开始安装。

**2. 环境安装**

打开「环境安装」菜单，按场景选择开发环境（见下节）。场景是一组运行时的组合，选定后确认清单即可安装；菜单中也提供「自定义安装」，可逐项勾选并指定主版本。

**3. 手动安装（不再提示）**

跳过安装，此后进入终端不再弹出该菜单，工具自行安装。如需恢复菜单，重置容器即可。

**4. 退出**

本次不安装，下次进入终端仍会提示。

安装失败不影响进入 shell，重新进入终端可再次尝试。

### 软件源选择

换源时可选择：

- `1) 自动探测（推荐）`：实测各镜像源在当前包管理器下的可达性，自动跳过失效或被墙的源。
- `2~6)` 指定镜像源：华为云、清华 tuna、中科大 ustc、腾讯云、阿里云。
- `0)` 不换源，保持默认。

换源前会备份原配置，失败自动恢复，不影响后续安装。内置 Alpine 的 rootfs 保持官方源，需要国内源时在此菜单切换。

## 随时安装开发依赖（aicode）

初始化菜单仅在首次进入终端时弹出一次。之后如需安装其他运行时（例如 Java 或 Go），在终端执行命令 `aicode` 即可打开「环境安装」菜单。

`aicode` 按场景安装，选定场景并确认清单即可：

| 场景 | 安装内容 |
| --- | --- |
| 通用开发 | 基础工具 + Node.js + Python 3 |
| Python 开发 | 基础工具 + Python 3 + pip |
| Node.js / 前端开发 | 基础工具 + Node.js + npm |
| Kotlin / Android 开发 | 基础工具 + JDK 17 + Android SDK |
| Flutter 开发 | 基础工具 + JDK + Android SDK + Flutter SDK |
| Java 开发 | 基础工具 + JDK |
| Go 开发 | 基础工具 + Go |
| Rust 开发 | 基础工具 + rustc + cargo |
| PHP 开发 | 基础工具 + PHP + Composer |
| 仅基础工具 | bash、curl、ripgrep、git |

基础工具（bash、curl、ripgrep、git）在任何场景下都会安装。场景默认安装软件仓库的最新主版本；如需指定版本，使用菜单中的「自定义安装」逐项勾选。菜单中还支持单独换软件源、查看已安装的运行时。

「Kotlin / Android 开发」与「Flutter 开发」属重场景：会从国内镜像下载 JDK、Android SDK（含 build-tools、platform-tools）及 Flutter SDK，耗时较长、占用存储较多。建议在 Debian / Ubuntu 镜像中安装（内置 Alpine 因使用 musl libc 需额外处理）；ARM64 设备会自动替换为可执行的 aapt2 等原生二进制。ARM64 容器可直接构建 Flutter debug APK，release 包需额外补装转译工具，见《在容器中构建 Flutter release APK》。安装完成后，新开终端会自动带上 `JAVA_HOME`、`ANDROID_HOME` 等环境变量，具体编译步骤见「进阶教程」中的《在容器中编译 Android 应用》《在容器中编译 Flutter 应用》。

终端右上角的设置图标打开终端设置面板，可调整配色主题、字号、字体与光标样式。

## 自定义镜像

内置 Alpine 可满足多数场景。如需 Debian / Ubuntu，或预装特定工具链的环境，可自行添加镜像，有两种方式。

### 方式一：内置镜像下载（推荐）

1. 打开「设置 → 容器与镜像」，点击右上角下载图标。
2. 页面列出可下载的镜像（Alpine、Ubuntu、Debian 等），点击一行查看详情并下载。
3. 右上角可切换下载源（官方源 / 华为云 / 阿里云 / 腾讯云），国内网络建议选国内源。
4. 下载完成后在详情中明确选择 **PRoot 或 CHROOT**。PRoot 点击「导入」按原流程加入列表；CHROOT 阅读写盘和 Root 提示后点击 **添加并创建实例**，保存新配置后自动创建同一个新实例。详情及下载页显示真实进度和结果，创建完成后仍须返回容器列表明确选中，不会悄悄导入成另一运行时。

已下载的镜像可重复导入；左滑可删除已下载的镜像文件。

下载页右上角的「多选」按钮（方框带勾的图标）可一次清理多个下载文件：进入多选后每行左侧出现勾选框，顶部操作条给出「全选 / 取消全选」与删除按钮，确认后选中的镜像文件一并删除（已导入的容器将无法再从这些文件解压，但已解压好的容器不受影响）。只有**已下载且文件存在**的条目能勾选，未下载的勾选框是灰的。

**版本信息会自动更新**：列表中的版本号由上游发布信息刷新，上游放出新补丁后不用等 App 更新就能看到，断网时则使用内置的版本清单。因此：

- **点进详情能看到精确版本**：Debian 这类「只写主版本」的发行版，详情里会显示实际补丁号（如 `12.15`），与真正下载到的内容一致。
- **支持状态角标分三档**：`即将停止支持` 表示某个支持期 30 天内结束（如 Alpine 3.21 于 2026-11-01 停止维护）；`已进入 ESM / LTS 延长支持` 表示常规支持已结束、但上游的延长支持计划仍在提供安全更新（Ubuntu 20.04 走 ESM、Debian 12 走 LTS）；`已停止支持` 表示连延长支持期也结束了。**点进详情能看到两个支持期的确切日期**，据此判断还能用多久。三档都能照常下载，只是建议优先选常规支持期内的分支。
- **已经下载过的镜像出现「有新版可下载」**：说明上游发布了新补丁（常见于安全修复）。重新下载再导入即可，旧的下载文件可左滑删除。升级到本版本前下载的镜像也能识别——版本号从下载文件名里取，不需要重新下载一次才知道有新版。
- **下载会自动校验完整性**：Alpine 与 Ubuntu 的镜像带官方 SHA-256，下载完会核对，不一致会提示校验失败并删除半成品；Debian 的上游只提供构建产物、没有校验和，因此不校验。
- **腾讯云源只提供 Alpine**：其 Ubuntu 镜像长期未同步补丁版本，因此该源下 Ubuntu 会显示「当前源暂无此镜像」，切回官方源或华为云 / 阿里云即可。

### 方式二：手动导入镜像文件

需要特定版本或发行版时，可自行准备 rootfs 镜像导入。

**镜像要求**：

- 压缩格式：`.tar.gz`、`.tgz`、`.tar.xz`、`.txz`
- 内容须为完整的 Linux rootfs（文件系统根目录，包含 `/bin/sh` 或其它 shell）
- 架构须与设备匹配：ARM64 设备用 aarch64 镜像，x86 设备用 x86_64 镜像

**镜像来源**：

- Alpine（体积小、启动快）：`https://alpine.linuxhub.cn/alpine/edge/releases/`，在 aarch64 目录下选 `alpine-minirootfs-*-aarch64.tar.gz`
- Ubuntu：`https://cdimage.ubuntu.com/ubuntu-base/releases/`，选 `ubuntu-base-*-base-arm64.tar.gz`
- Debian：可从 Docker Hub 官方镜像（如 `arm64v8/debian`）导出

具备 Docker 环境时，可从任意镜像导出 rootfs：

```bash
docker pull debian:bookworm
docker create --name temp-rootfs debian:bookworm
docker export temp-rootfs | gzip > debian-rootfs.tar.gz
docker rm temp-rootfs
```

也可在已有 Linux 环境中用 `debootstrap`（Debian / Ubuntu）或 `alpine-make-rootfs`（Alpine）自行制作。

**导入步骤**：

1. 打开「设置 → 容器与镜像」，点击右上角 +，选「本地镜像」。
2. 填写配置：
   - **运行时**：新建时明确选择 PRoot 或 CHROOT；创建后不能就地转换。CHROOT 不继承 PRoot 额外挂载或参数。
   - **名称**：镜像配置的别名。
   - **shell 路径**：容器内 shell，如 `/bin/sh` 或 `/bin/bash`。
   - **镜像文件**：选择准备好的 rootfs 文件。保存时会复制一份到 App 私有目录，此后重置容器均从该副本重新解压，不依赖原始文件；删除镜像时副本一并清理。
   - **挂载**（可选）：将手机目录挂进容器，见下文「把手机目录挂给 AI 用」。
   - **proot 参数**（可选）：逐项添加，原样追加到 PRoot 启动参数。
   - **环境变量**（可选）：注入容器内进程的键值对。
3. PRoot 点击「添加」保存；CHROOT 阅读写盘及 Root 前提提示后点击 **添加并创建实例**，配置保存后立即尝试创建，不需要再去实例卡创建。仅按明确勾选设置默认容器，不会自动激活；完成后在列表中明确选中该配置才能使用。若创建失败且配置保存成功，配置会保留以便核对状态后手动重试，不自动删除未知现场。

首次使用 PRoot 自定义镜像时 App 会解压 rootfs 到私有目录，耗时取决于镜像大小。自定义镜像默认不配置国内软件源，可在首次进入终端的初始化菜单中切换。

### 常见问题排查

**安装软件报错**：由容器内硬链接不可用导致。编辑镜像 → proot 参数 → 添加 `--link2symlink` → 保存，重新进入终端。使用内置下载功能导入的镜像已默认带有该参数。

**方向键显示为 `^[[A`**：当前 shell 为 `sh`，不支持行编辑。编辑容器，将 Shell 改为 `/bin/bash`，即可获得方向键、历史记录与补全。

## 把手机目录挂给 AI 用

AI 运行在容器内，默认只能看到工作区，无法访问手机公共存储。如需访问，需将手机目录挂进容器：

1. 确认存储权限已授权。首次使用时会弹出权限请求；若此前拒绝过，前往系统设置 → 应用 → AiCode → 权限 → 存储 开启。
2. 打开「设置 → 容器与镜像」，编辑当前使用的容器。
3. 在「挂载」中添加一条：**本地目录**填手机上的路径（如 `/sdcard/Download`），**容器目录**填容器内路径（如 `/mnt/Download`）。
4. 保存后重启终端会话，AI 即可通过容器内路径访问。

::: warning 按需挂载
仅挂载需要的子目录，不要直接挂载整个 `/sdcard`——那会将手机中所有文件暴露给 AI，存在隐私泄露风险。
:::

例：如需让 AI 查看 App 日志，将本地目录 `/storage/emulated/0/Android/data/com.aicode/` 挂到容器 `/mnt/aicode`，即可读取 `/mnt/aicode/files/logs/` 下的日志。注意 `Android/data/` 下只能访问 AiCode 自身的目录，其他应用的目录受分区存储限制无法访问。

如需处理的仅为单个文件，更简便的方式是将其复制进工作区，AI 默认即可访问。

## 全部删除后的行为

删除所有容器后，App 的聊天等功能仍可使用；执行环境尚未就绪时不会把旧 CHROOT 操作偷偷切到其它容器。重新打开「容器与镜像」，在空状态页面恢复内置 Alpine 或添加并明确选择新镜像后，再从原入口重试。
