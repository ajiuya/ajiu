# 软件权限

「设置 → 软件权限」集中管理 App 需要的系统级权限、本机 Root 总开关与手机构建设置。系统权限状态在页面恢复时（包括从系统设置页返回）自动刷新，已授权的状态项点击后不会有反应；Root 和手机构建是可以主动开关的独立设置。

后台保活、屏幕常亮、AI 完成通知、实时通知、授权审批通知这几个开关在[后台运行](/guide/background-run)页。

## 手机构建

默认关闭。开启后，本机 Linux 容器中的普通 `./gradlew` 或 `gradle` 会默认采用手机档；关闭后恢复项目与原有用户级 Gradle 配置，不修改项目文件。已打开的终端在**下一次构建**读取新设置，正在运行的构建不受影响，已选择的参数在关闭后仍然保留。

点击「构建参数」打开调节面板，调整后点「保存」；取消或直接关闭面板不会应用草稿。保存遇到配置冲突或写入错误时会显示提示，不会把未生效的设置显示为保存成功。

| 参数 | 可选值 | 手机档默认值 |
| --- | --- | --- |
| Gradle 最大堆内存 | 2 GB、2.5 GB、3 GB | 3 GB |
| 常驻 Gradle 进程 | 开启 / 关闭 | 关闭 |
| 并行构建 | 开启 / 关闭 | 关闭 |
| Gradle worker 上限 | 1、2、3、4 | 1 |
| 单元测试最大堆内存 | 512 MB、768 MB、1 GB、1.5 GB、2 GB | 1 GB |

手机档还会将 Gradle 最大元空间设为 512 MB，使用进程内 Kotlin 编译、关闭配置缓存，并将 JVM 单元测试限制为每项任务最多 1 个测试进程。

设置仅作用于**本机容器默认 Gradle 用户目录**，保留原有配置（包括 Android 构建所需的工具路径）。远程 SSH 和 CI 不受影响；主动指定其他 Gradle 用户目录或命令行参数时，以显式配置为准。自定义容器若通过额外绑定改写默认 Gradle 目录，需先检查绑定设置；本功能不会追踪绑定或符号链接去覆盖其他位置的文件。

::: warning 内存与常驻边界
堆上限不是构建的总内存上限。Gradle、测试 JVM、原生工具和系统各自占用内存；增加 worker、开启并行或常驻都会增加占用。常驻开关只控制 Gradle 的复用偏好，不能保证 PRoot 退出或 Android 系统回收后进程仍然存在。关闭常驻时仍可能出现本次构建专用、构建结束后退出的 JVM，也不会自动停止已有 daemon。
:::

本仓库的 `scripts/gradle-mobile.sh` 是另一条**显式固定手机档**入口，它自己的参数优先；要让面板设置生效，使用普通项目 wrapper，详见 [编译 Android 应用](/advanced/build-android-app)。

## 安装未知应用

显示当前是否已允许。未允许时点这一行会跳到系统设置里本应用的「安装未知应用」开关页，开启后才能安装 APK。

## 访问存储空间

显示当前是否已授权。未授权时点击会弹系统权限申请框，用于读写工作区文件与容器镜像。

如果权限已被永久拒绝（系统不再弹框），会有弹窗提示，点「去设置」手动开启。

## 忽略电池优化

显示当前是否已豁免。未允许时点击跳到系统的电池优化申请页，对本应用豁免省电策略，降低后台进程被杀的概率。

## 自启动管理

点击跳转到你设备厂商（小米、华为、OPPO、vivo、魅族等）的自启动管理设置页，允许 App 在开机或被系统终止后自动拉起。厂商设置页打不开或匹配不到厂商时，会回退到本应用的详情页。

这一项配合「后台运行保活」和「忽略电池优化」一起使用，能进一步降低后台被终止的概率——国产 ROM 的后台限制比较激进，若长任务经常被打断，建议三项都开启。

## Shizuku 授权

Shizuku 让本应用可以执行系统命令，是 AI 的 `Shizuku` 工具的前提。这一行显示当前状态：

- **未安装 / 服务未运行**：点击打开 Shizuku 应用，按其中的指引安装或启动服务。
- **未授权**：点击申请授权，在 Shizuku 弹出的授权框里选「允许」。
- **身份待确认**：已授权，但暂时无法读取服务身份。点击重试，或打开 Shizuku 核对服务并重新连接；身份未确认时不执行命令，也不会显示为 Root 已就绪。
- **身份不受支持**：服务身份不属于 ADB shell 或 Root，请在 Shizuku 中核对启动方式后重新连接。
- **已就绪**：服务为 ADB shell 且系统授权完成。
- **Root 已就绪**：服务为 Root 且系统授权完成，命令可按该真实身份及当前工具策略执行。

需要 Root 启动时，手机须已有 root，由你在 Shizuku 应用中选择 Root 启动并授权本 App；阿九工作台不代为启动外部 Shizuku 的 Root 服务。从 Shizuku 返回本页时状态自动刷新，未授权时会先提供申请入口，获准后才确认身份。

系统授权和真实连接身份仍是执行前提。**可确认只读的宿主系统文件操作默认放行；修改宿主，或未知脚本、动态路径、交互行为等无法确认是否只读时先审批**，实际只读脚本也可能弹窗。可仅本次允许（`ONCE`），或本会话始终允许（`ALWAYS_SESSION`）：后者覆盖本聊天 session 中 Shizuku 同一 source／identity 的全部后续宿主修改与不确定操作，包含不同命令和目标，不限当前命令，不跨工具、来源、身份或父子／其他会话。新宽授权仅存内存，进程重启清除；来源、身份或连接、相关 Root 代际、Profile 配置内容或选择、实例变化后需重审。显式禁止与真实系统授权仍优先；每条命令仍消费完整命令及当前身份绑定的单次内部许可，不为取得新许可另弹工具确认，也不是无限 OS Root 权限。判断只是有限静态识别，不执行或打开脚本，不能保证符号链接、`PATH` 或任意程序的实际副作用，不提供沙箱保证。

服务重启、断开、切换身份或撤销系统授权后，旧内部许可、相关会话授权与来源捕获失效；新请求须重新核验真实身份，身份或来源状态为 UNKNOWN 时拒绝执行，不把未确认身份显示为可用。产品不再仅因命令含 `su`／`sudo` 字样就拒绝，但 ADB shell 不会因默认放行而被当作 Root，实际提权仍取决于真实 OS 授权；需要 Root 时应准备 Root 服务或独立 Root 通道，不能借用另一通道的身份。用法与排错见 [Shizuku 工具](/guide/shizuku)。

## Root 总开关

**默认关闭**。仅当手机已经取得 root、且系统 su 管理器允许本应用执行时，才可能使用独立的宿主 `Root` 工具；开启本页开关不会为未 root 的手机取得 root，也不提供 root 安装或漏洞利用。

- 开启且系统 su 授权有效后，可确认只读的宿主系统文件操作默认放行；修改宿主或无法确认是否只读时先审批。可仅本次允许，或在本聊天会话中允许 Root 同一来源及身份的全部后续宿主修改与不确定操作，包含不同命令和目标，不限当前命令。新宽授权仅存内存，进程重启清除；来源、身份、Root 代际、Profile 配置内容或选择、实例变化后需重审。显式用户拒绝及项目／全局禁止始终优先。
- 每条命令仍核对完整内容、Root 启用代际与真实系统授权，只取得绑定本次调用的内部一次性执行许可，防止替换命令或重复使用；这一内部许可不新增弹窗。系统 su 拒绝或状态 UNKNOWN 时，不执行，也不显示为可用。
- 关闭会撤销待审批请求与未消费的执行许可，使相关会话 grant 和关联本次 Root 启用代际的旧来源捕获失效，并终止本应用管理中的 Root 进程。再次开启后，新操作按当前策略重新绑定并核验系统 su 授权，必要时重新审批，不恢复旧捕获、旧许可或宽授权。
- 关闭不等于回滚，无法撤销已经完成的修改，也不保证终止任意脱离本应用管理的后台进程。
- 开关、系统 su 授权与本机身份不随 App 备份迁移，备份也不能恢复单次批准、新的宿主宽范围会话授权或内部许可。PRoot／SSH 的 `sudo`／`su` 及高危提权仍按原有完整精确命令策略处理，Shizuku 的启动和系统授权仍独立管理；独立计划、插件信任、依赖准备、当前 CHROOT 来源、实例身份及清理核验和 CREATE／STOP／REMOVE 确认不变；单条历史任务 UNKNOWN 保留诊断但不单独阻止新任务。异常实例删除核验通过后无需重启，失败不会报告已删除。

Root 输出有长度上限，不会自动归档到当前 SSH 服务器，但**作为任务结果仍会交给你已选择的 AI 服务商**。执行前请确认命令范围和可能读取的敏感数据；完整授权边界见 [Root 工具](/guide/permissions#root-工具)。
