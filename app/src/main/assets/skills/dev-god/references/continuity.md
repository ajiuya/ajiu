# 协作与交接

长任务、中断恢复或实际需要多 Agent 时使用。单个局部修改不必建立持久状态体系。

## 并行只用于可独立推进的工作

主代理仅在当前可用代理清单有匹配角色时，使用 `task` 委派可独立推进的工作，为每项任务给出目标、可读/可写范围、输入、产物与验收条件；角色名按当前清单填写，不硬编码其他宿主的代理名称。子代理不能嵌套派发，需要协调时使用 `messageParent`。明确文件所有权；存在先后依赖的改动顺序执行，避免两个 Agent 同时覆写相同文件。检索、实现和审查都可委派，取决于用户任务和现有授权。

委派不会扩大权限。计划审批、Root 单次许可与会话工具授权不跨会话继承；项目/全局显式 `DENY` 仍优先。子 Agent 汇报是待核对结果，主 Agent 核对实际差异、验证对应的代码版本和环境；证据足以覆盖当前产物时复用，仅对后续变化或证据缺口补验。独立审阅时提供原始任务和产物，避免先告诉审阅者“这里一定有错”。后台派发设置完成通知后等待真实通知，不通过反复查询或 sleep 制造进展。没有委派工具时按同一验收要求串行执行，不虚构多个角色已经独立检查。

## 仅在确实需要时保存一个交接点

优先使用 `todo` 跟踪当前多步骤任务，并按进度更新，全部完成后提交空列表清空。需要跨会话交接时，遵循用户指定范围与项目已有记录约定；未要求时不额外创建 README、交接文档或多层日志。

交接应包含：

- 目标与仍然适用的用户约束。
- 已完成事项、对应文件/版本和可定位的验证证据。
- 当前未完成项、阻塞及最先执行的下一步。
- 当前运行的任务/进程、环境区别和必要恢复方法。

不记录凭据、无关聊天或未验证为事实的推断。只读审查的交接沿用只读范围，必要材料放允许的临时位置。

## 恢复先校验现场

读最近有效的记录，检查当前目录、源码版本、用户新增改动及运行状态。标记过期证据，只补变化涉及的验证；不因看见“已通过”就无条件沿用，也不把已经完成的任务全部重做。

长期经验只有在确有复用价值且符合项目/宿主记录规则时保存；写清适用范围、证据和失效条件。后续事实推翻旧结论时更新或废弃它，不能把一次局部修复升级为所有项目的硬规则。
